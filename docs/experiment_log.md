# 实验记录：RAGTruth 幻觉检测 critic

记录每个实验的**目标、设置、结果、结论**，以及过程中踩过的坑。新实验跑完后追加到对应章节，结论被后续实验修正时在原处注明。
指标口径、数据和代码说明见文末「附：口径与文件」。

## 0. 总体目标（2026-10-26 定）

要验证的是**技术本身**，不依赖医学数据的正确性。以 Claude 最高档模型作为「人工」的最终裁判，设计对照实验回答四个问题：

1. **GRPO vs SFT**：GRPO 是否真的比 SFT 更能提升幻觉检测效果，并记录过程中的问题。
2. **合成数据 vs 人工标注**：合成数据的提升体现在哪里。
3. **critic 循环挖难样本**：从正确答案合成错误答案 → critic 判断 → 把 critic 识破不了的加入训练 → 循环。这种做法是否有用？担心的是合成错误太简单，critic 全部能识破。
4. **人工修正的增益**：主要体现在难样本合成和复检上。

主线数据：RAGTruth（公开幻觉检测基准）。训练只用 1/10（`train_sub`，1,410 条回答）。
硬件：先在本地用最小模型（Qwen3-0.6B，RTX 4070S 12GB）验证，再到 AutoDL RTX 5090 上扩展，包括 Qwen3.5-9B LoRA critic，以及 Qwen3.5-35B-A3B-GPTQ-Int4 做生成和标注。

**评价标准（2026-10-27 定）：以召回为主。** 精确率要用 Claude 修正后的标签估计（见 §6），因为人工标签漏标多，按人工标签计算会严重低估精确率。

## 1. 数据准备

### 1.1 RAGTruth 转换（`ragtruth/convert.py`）
- 回答按句切分。句子标签取自人工标注的幻觉片段：与片段重叠 ≥ 3 个字符的句子记为幻觉，类型分 conflict 和 baseless。
- **粗粒度句（coarse）**：如果一个人工标注片段覆盖 ≥ 3 句，这些句子不作为训练样本，也不计入句子级指标。原因是标注员整段标出时，句子级标签不可信。测试集有 147 句。
- 划分：`train_sub`（按 source 取 1/10）和 `train_pool`（其余部分，用作合成种子）；测试集使用原始 test（2,675 条回答，18,772 句非粗粒度句，其中幻觉句 1,404 句，占 7.5%）。

### 1.2 补写证据和理由（`ragtruth/annotate.py`）
- 人工标注只有片段、类型和简短备注。补写时，把真值交给较大的模型，让它为每句写出 evidence（原文逐字片段，允许「开头 ... 结尾」的写法）和 reason（英文说明，不出现结论词）。
- 校验项：证据逐字可在原文中定位；conflict 句必须给出证据；理由中不出现结论词、"ground truth"、"annotator"；理由与真值一致（`reason_consistent`）。模型可以标记 "disputed"，但只有当理由确实与真值相反时才采纳。
- v1 用 Qwen3.5-9B Q4_K_M（本地 llama.cpp），v2 改用 Qwen3.5-35B-A3B Int4（5090）。
- 构建（`ragtruth/build.py`）：逐句取舍，证据用 rapidfuzz 模糊修正。比例默认 1:3（幻觉 : 无幻觉），`--faithful_per_bad 0` 表示保持自然比例。
- 产物：`train_sub35_r3.jsonl`（3,484 条，1:3）、`train_sub35_nat.jsonl`（8,298 条，自然比例，幻觉句约 8%）。

### 1.3 critic 输出格式（用户定）
- 先写 evidence，再写 reason，最后给 type（conflict / baseless / none）和 verdict。
- 在给出结论之前，**格式上不能看出有没有幻觉**：有问题的句子和没问题的句子都写证据和理由，写法相同。
- 逐句检查：一次调用只判一句，但输入里给出完整的 source 和完整回答。

## 2. 基线：零样本、回答级、逐句 v1/v2

| 实验 | 设置 | 句子级 P / R / F1 | 回答级 F1 | 备注 |
|---|---|---|---|---|
| 零样本 Qwen3-0.6B | 不训练 | 0 / 0 / 0 | 0 | 完全识别不出 |
| ① 回答级 0.6B | 一次判整条回答，列出错误句；1,410 条回答，自然比例 | 0.537 / 0.578 / 0.557 | 0.741 | 本地 SFT |
| 逐句 v1 0.6B | 9B-Q4 补写，1:2 | — / — / 0.434 | 0.626 | 误报 2,104；理由与判定不一致 317 句 |
| 逐句 v2 0.6B | 35B 补写 + 校验，1:3 | 0.340 / 0.717 / 0.461 | 0.659 | 误报 1,896；不一致 167 句 |
| 逐句 v1 9B | 同 v1 数据，LoRA | 0.470 / 0.816 / 0.596 | 0.740 | 类型准确率 0.90 |
| **逐句 v2 9B** | 同 v2 数据（1:3），LoRA | 0.508 / **0.803** / 0.623 | 0.772 | 回答级召回 0.907 |

**目标**：先在小模型上跑通「逐句 + 证据 + 理由」格式，再看换大模型、改进补写质量各带来多少提升。

**结论**
- 补写质量提升（9B-Q4 → 35B + 校验）对 0.6B 和 9B 都有帮助：F1 分别 +0.03 和 +0.03。
- 模型规模影响最大：同一份数据，9B 比 0.6B 高约 0.16 F1。
- 错误分析（2026-10-26）：
  - 训练标签里有人工漏标；
  - 「理由说有问题、判定却说没问题」这种不一致是从数据里学来的，v2 加了一致性校验后减少了一半；
  - 结构化数据（JSON）上的错误随模型变大而减少；
  - GPT 写的回答里的细微错误始终最难。

## 3. 35B 全量复核与 Claude 仲裁：人工标签有多可靠

**目标**：0.6B 的误报很多，需要先弄清楚是模型问题，还是人工标签漏标。

**设置**
- 35B 独立判断测试集的每一句（`ragtruth/adjudicate.py`），结果与人工标签对比。
- 分歧句分层抽样，交给 Claude Opus 独立裁定（`ragtruth/arbitrate.py`，用 `claude -p` 调用，effort high）。Claude 看不到人工标签和 35B 的判定。

**结果**
- 35B 与人工一致率 79.4%。35B 判出的幻觉句占 26.8%，人工只标了 7.5%。35B 作为 critic 的句子级 F1 只有 0.401（偏严）。
- Claude 裁定：
  - 「35B 判有、人工判无」：60 句中 35 句 Claude 同意 35B，推算人工漏标约 2,180 句，35B 误报约 1,560 句；
  - 「人工判有、35B 判无」：20 句中 16 句 Claude 同意人工。
- 费用：$1.79。

**结论**
- **RAGTruth 人工标签中，「无幻觉」漏标严重，而人工标为「有幻觉」的基本可靠。**
- 只用 35B 单方面修正标签会偏乐观，因为 35B 本身也误报很多。需要对称复核，或者引入第三方（Claude）。

## 4. 格式对比实验（实验 1 的一部分，0.6B，5090）

**目标**：用户记得「以前一次输入、输出很少的版本效果更好」。需要把粒度（逐句 / 回答级）、是否写理由、正负比例这几个因素拆开，看清楚各自的影响。

| 编号 | 粒度 | 输出格式 | 数据 | 句子级 P / R / F1（95% 区间） | 回答级 R / F1 | 摘要召回 |
|---|---|---|---|---|---|---|
| ② e2 | 逐句 | 只给 type + verdict | 自然比例 8,298 条 | 0.643 / 0.617 / **0.630**（0.599–0.646） | 0.739 / 0.766 | 0.36 |
| ③ e3 | 逐句 | 证据 → 理由 → type → verdict | 同上 | 0.515 / 0.582 / 0.547（0.525–0.570） | 0.738 / 0.714 | 0.25 |
| ④ e4 | 逐句 | type → verdict → 证据 → 理由 | 同上 | 0.633 / 0.563 / 0.596（0.561–0.610） | 0.695 / 0.744 | 0.25 |
| v2 | 逐句 | 证据 → 理由 → type → verdict | 1:3，3,484 条 | 0.340 / 0.717 / 0.461 | 0.875 / 0.659 | 0.48 |
| ⑤ e5 | 回答级 | 每句一行证据，再列错误句 | 774 条回答 | 0.257 / 0.432 / 0.323 | — / 0.646 | — |
| ⑤b e5b | 回答级 | 只列错误句 | 同 e5 的 774 条 | 0.323 / 0.611 / 0.423 | — / 0.698 | — |
| ① | 回答级 | 只列错误句 | 1,410 条回答 | 0.537 / 0.578 / 0.557 | — / 0.741 | — |

**结论**
1. **比例**：v2 和 e3 只有比例不同。1:3 让 F1 从 0.547 降到 0.461，原因是精确率从 0.52 跌到 0.34。但召回从 0.58 升到 0.72。改成以召回为主后，1:3 不一定是坏事，见 §6。
2. **写理由（0.6B）**：e2 和 e3 只有格式不同，e3 低 0.083 F1，置信区间不重叠。原因定位见 §5。
3. **顺序**：把判定放到最前（e4），精确率就恢复到 e2 的水平（0.633 vs 0.643）。这说明「先写理由再下结论」时，理由写偏会把结论带偏，这是精确率损失的主因。但 e4 的召回仍比 e2 低 0.054，说明训练目标里带证据和理由会稀释判定 token 的学习信号。
4. **回答级格式**：让 0.6B 一次为十几句逐句写证据，F1 会掉 0.10（e5 vs e5b），摘要任务掉得最多。回答级格式对数据量也很敏感：同样格式，774 条只有 0.423，1,410 条有 0.557。逐句拆分后每条回答变成多条样本，同时缓解了数据量问题。
5. **9B 上的格式对比（诊断 B，2026-10-27）**：v2 数据（1:3）不变，只换格式。只给判定的句子级 P/R/F1 是 0.599 / 0.806 / **0.687**（区间 0.667–0.707）；证据 + 理由（v2）是 0.508 / 0.803 / 0.623（区间 0.609–0.647）。回答级召回分别为 0.888 和 0.906，标为幻觉的比例分别为 10.1% 和 11.7%。**9B 上两种格式的召回几乎一样**，差别只在精确率，而 9B v2 的误报里有 78% 是真幻觉（§6），所以这个差距有相当一部分是标签噪声造成的。结论：以召回为主时，9B 写证据和理由不会损失召回，还能给出可核查的解释；0.6B 写理由会掉召回（e4 vs e2），这是模型容量不够的问题。
6. **对召回来说，训练数据的影响远大于格式**：几种格式的召回差 ≤ 0.05，而合成数据能把召回提高 0.07–0.09（§7）。

## 5. e3 比 e2 差的原因定位（诊断 A，以及 ④ 的结论）

**目标**：在同一份数据上，为什么加了理由反而变差？要定位到具体原因。

**方法**
- e2、e3 在 18,772 个测试句上逐句对比（`scripts/analyze_e2_e3.py`，判定不同的句子存在 `outputs/rt/analysis/e2_vs_e3_diff.json`）。
- 分歧句分层抽 80 句交给 Claude 仲裁（`ragtruth/arbitrate_pair.py`）。

**发现**
1. **判断在写理由的过程中就已经做出了**。e3 只错的句子里，判定和它自己写的理由高度一致：漏报中 97%，误报中 76%（其余多为对照措辞，规则没识别出来）。证据定位基本正常（91–93%）。所以错在理由本身，判定只是照着理由走。
2. **理由出错的三类情况**：
   - 意译、概括类句子找不到逐字依据，就写成「原文没提到」。这是主因：e3 多出来的误报句，实词出现在原文中的比例是 49%，正确判为无幻觉的句子是 66%；所选证据覆盖的词也只有 21%，后者是 42%。数据转文本最多，474 句中占 248 句。
   - 理由本身读错原文，比如把 JSON 里的 `upscale: False` 读成 True。训练时理由由 35B 写好，测试时则是 0.6B 自己生成，一处出错，后面跟着错。
   - 有一部分「误报」其实是人工漏标。
3. **Claude 仲裁**：
   - e3 多出来的误报里 43% 是真幻觉，e2 多出来的误报里 60% 是真幻觉；两者多出来的漏报里，Claude 基本都同意人工。
   - 按 Claude 的判断修正标签后：e2 的 F1 从 0.630 变为 0.651，e3 从 0.560 变为 0.626。**两者的差距从 0.070 缩小到 0.025**。
   - 局限：每层只抽了 15–30 句，误差在 ±15–20 个百分点左右；Claude 用的也是「证据 + 理由」格式，可能与 e3 的判断风格相近。

**结论**：e3 与 e2 的差距约三分之二来自测试集漏标。剩下约 0.025 是格式本身造成的，体现在精确率上，原因是先写理由再下结论。

## 6. 召回视角与真实精确率（诊断：9B 误报复核）

**目标**：用户决定以召回为主，需要知道当前各模型的召回，以及在修正标签后的真实精确率。

**召回**（人工标出的 1,404 个幻觉句；人工判有的标签基本可靠，所以按人工标签算的召回可信）：

| 模型 | 句子级召回 | 回答级召回 | 召回：数据转文本 / 问答 / 摘要 |
|---|---|---|---|
| 9B v2（证据 + 理由，1:3） | **0.803** | **0.907** | 0.85 / 0.72 / 0.71 |
| 0.6B v2（1:3） | 0.717 | 0.875 | 0.80 / 0.64 / 0.48 |
| 0.6B e2 或 e3（任一判为幻觉） | 0.703 | 0.830 | 0.81 / 0.57 / 0.44 |
| 0.6B e2 | 0.617 | 0.739 | 0.72 / 0.47 / 0.36 |
| 0.6B e3 | 0.582 | 0.730 | 0.69 / 0.48 / 0.25 |

**9B v2 真实精确率**（`ragtruth/arbitrate_fp.py`）：从 9B v2 的 1,063 个误报里抽 60 个交给 Claude，**其中 47 个（78%）是真幻觉**。估算真实精确率 **0.895**（95% 区间 0.84–0.94），按人工标签只有 0.515。按任务分：数据转文本 26/29，问答 12/17，摘要 9/14。

**结论**：9B v2 召回 0.80，真实精确率约 0.9，以召回为主的话已经可用。后续实验以 9B 为主，0.6B 用于快速验证方法。精确率下限还需要用户确定。

## 7. 合成错误样本与 critic 挖难样本（实验 2、3、4）

### 7.1 合成（`ragtruth/synth.py`）

**设置**
- 种子：从 `train_pool` 中整条回答都没问题的 7,056 条回答里，按任务分层抽 3,000 条，每条挑一句有事实内容的句子。conflict 和 baseless 各占一半，每条随机指定一种改法（共 13 种，见 7.3 的表）。
- 生成：用 35B 一次调用写出改后的句子、改后句的证据和理由，以及原句的证据和理由（用于成对加入）。few-shot 用 train_sub 里同任务、同类型的真实幻觉句。
- 校验：改动大小、长度、证据逐字定位、理由与类型一致；不通过的反馈给模型重写，最多 2 次。
- 复核：把原句和改后句随机排成 A/B，让 35B 逐一判断。要求原句「有依据」，改后句的类型与指定的一致。
- **成对加入**（用户定）：每加一条错误句，同时加入它的原句作为无幻觉样本。

**结果**：3,000 条中 1,837 条通过（61%）。
- 规则校验通过 2,618 条（87%），主要失败原因：改动过大、证据不是逐字摘录、理由与类型不一致。
- 复核通过 1,837 条（70%），主要淘汰：类型与指定的不符 454 条；改了但其实不算错 248 条；原句本身被判为有问题 79 条。
- 6 个「任务 × 类型」组合各有 270–369 条。

### 7.2 critic 识破率

每条错误句采样 4 次（温度 0.7），识破率低于 50% 记为难样本（`ragtruth/mine.py mine`）。

| critic | 平均识破率 | 难样本 | 4 次全部识破 | 原句误报 |
|---|---|---|---|---|
| 0.6B e3 | 0.30 | 1,216（66%） | 260 | 60 |
| 9B v2 | 0.71 | 460（25%） | 1,060 | 64 |

- 9B 的 460 条难样本中，437 条 0.6B 也识破不了，基本是 0.6B 难样本的子集。

### 7.3 按改法看难度

| 改法 | 0.6B 难样本比例 | 9B 难样本比例 |
|---|---|---|
| 加原文没有的结论或概括 | 87% | **51%** |
| 加原文没有的原因或动机 | 81% | 39% |
| 调换主客体 | 86% | 34% |
| 加评价或建议 | 73% | 32% |
| 加看似合理的常识 | 59% | 32% |
| 改因果或先后顺序 | 74% | 30% |
| 列表多加一项 | 67% | 26% |
| 加一个具体细节 | 61% | 27% |
| 改属性 | 60% | 12% |
| 改实体名称 | 54% | 9% |
| 改否定或极性 | 58% | 9% |
| 改日期或时间 | 41% | 8% |
| 改数字、数量 | 43% | 6% |

**结论（实验 3 的前提）**
- 「合成错误太简单，critic 全能识破」：**对 0.6B 不成立**。**对 9B 部分成立**：事实替换类（数字、实体、否定）9B 几乎都能识破，但推理、归因类仍有 30–50% 识破不了。
- baseless 比 conflict 难。三种任务的难度相近。

### 7.4 难样本有效率（Claude 抽查，`ragtruth/audit_synth.py`）

| | 0.6B 难样本 | 9B 难样本 | 被识破的样本 |
|---|---|---|---|
| 真幻觉比例 | 85%（40 条中 34 条） | **70%**（40 条中 28 条） | 100%（两边各 20 条） |

- 无效样本有几种：改了编号、改成病句但没改事实、加的信息其实原文支持。9B 的无效样本几乎都是「35B 以为加了原文没有的信息，其实就在原文别处」，比如 Data2txt 里别的评论已经提到。
- **规律：critic 越强，它识破不了的样本里无效样本越多。** 「挑 critic 识破不了的」必然会顺带挑进标签噪声，这正是人工修正（实验 4）应该发挥作用的地方。
- 用户决定（2026-10-27）：暂不做全量 Claude 清洗，最多抽查很少一部分。

### 7.5 加入训练：三组对照

| 组 | 加入的合成样本 | 0.6B（基础 e3 数据，8,298 条） | 9B（基础 v2 数据，3,484 条，1:3） |
|---|---|---|---|
| direct：直接加入 | 全部 1,837 对 | 训练集幻觉占比 22.6% | 待跑（机器 2） |
| critic：过 critic 后加入 | 难样本（0.6B 1,216 对 / 9B 460 对） | 幻觉占比 19.5% | 幻觉占比 30.2%，进行中（机器 3） |
| random：随机选同样条数 | 与 critic 组同条数 | 幻觉占比 19.5% | 进行中（机器 3） |

**0.6B 结果**（以召回为主；精确率按人工标签，会被低估）：

| 组 | 句子级 P / R / F1 | 回答级 R / F1 | 召回：数据转文本 / 问答 / 摘要 | 标为幻觉的比例 |
|---|---|---|---|---|
| 基线 e3 | 0.515 / 0.582 / 0.547 | 0.738 / 0.714 | 0.69 / 0.48 / 0.25 | 8.1% |
| direct | 0.387 / **0.655** / 0.486 | **0.831** / 0.651 | 0.73 / 0.56 / **0.47** | 12.4% |
| critic | 进行中 | | | |
| random | 进行中 | | | |

**阶段结论**：直接加入合成数据后，句子级召回 +0.073，回答级召回 +0.093，摘要召回接近翻倍（0.25 → 0.47）。但训练集幻觉占比也从 8% 升到 23%，召回提升有一部分来自比例变化。critic 组和 random 组样本条数、比例完全相同，等它们的结果出来，才能单独看出「挑难样本」本身的作用。

---

**0.6B 三组都已出结果**：direct（1,837 对）、critic（1,216 对）、random（1,216 对）三组的句子级召回分别是 0.655 / 0.656 / 0.648，回答级召回分别是 0.831 / 0.844 / 0.830，摘要召回分别是 0.47 / 0.44 / 0.43。critic 减 random 为 +0.008，95% 区间 [−0.012, +0.027]，没有区别。从 1,216 对加到 1,837 对，召回不再上涨，说明 0.6B 在约 1,200 对时已经接近数量饱和。

**9B 结果**（2026-10-27，单种子；括号内为 Claude 抽检 50 条修正后的精确率）

| 组 | 句子级 P / R / F1 | 回答级 R | 召回：数据转文本 / 问答 / 摘要 | 召回：GPT-3.5 / GPT-4 | 标为幻觉的比例 |
|---|---|---|---|---|---|
| 基线 v2 | 0.508 (0.895) / 0.803 / 0.623 | 0.906 | 0.85 / 0.72 / 0.71 | 0.58 / 0.68 | 11.7% |
| critic（460 对） | 0.414 (0.837) / 0.838 / 0.554 | 0.953 | 0.87 / 0.77 / 0.79 | 0.54 / 0.75 | 15.0% |
| random（460 对） | 0.479 / 0.843 / 0.611 | 0.927 | 0.88 / 0.79 / 0.74 | 0.62 / 0.68 | 13.0% |

**结论**：
- 条数相同时，挑难样本在句子级召回上没有优势。critic 组减 random 组为 −0.005，按回答配对的 bootstrap 95% 区间是 [−0.019, +0.009]。
- critic 组多报了 2 个百分点，精确率更低，这和 9B 难样本里约 30% 是无效样本相吻合。
- critic 组只在局部更好：摘要高 0.05，GPT-4 回答高 0.07，回答级召回高 0.026。
- 预判的「召回 +0.01–0.03」没有得到支持。下一步验证：加 oracle 门控把无效难样本去掉之后，critic 组能否超过 random 组。

**9B direct 组（全部 1,837 对，2026-10-27）**：
- 句子级 P / R / F1 为 0.459 / 0.821 / 0.589，回答级召回 0.932，标为幻觉的比例 13.3%；
- 分任务召回：数据转文本 0.86、问答 0.73、摘要 0.77。

**召回比随机 460 对（0.843）还低，说明 9B 在约 460 对时就已经数量饱和**，再加 4 倍的合成样本也没有带来更多召回（单种子，波动约 ±0.01–0.02）。所以「现在还处在数量未饱和阶段」这个解释不成立：在饱和区，挑难样本仍然没有胜过随机。目前更可能的原因是难样本里约 30% 是无效样本，下一步用 oracle 门控来验证。

**9B critic 组和 random 组各自多报的句子（Claude 抽检 50+50 条，2026-10-27，约 $2.2）**

| 人工判无、模型判有 | 句数 | Claude 判为真幻觉 |
|---|---|---|
| 两组都标 | 1,045 | 28/32（88%，来自之前的抽检） |
| 只有 critic 组标 | 588 | 24/50（48%，95% 区间 35–62%） |
| 只有 random 组标 | 220 | 25/50（50%，95% 区间 37–63%） |

结论：critic 组多报的部分并不比 random 组多报的部分更准，两层都是约一半真幻觉、一半误报。critic 组只是整体标得更多。

按 Claude 修正后估算：
- critic 组共找出约 2,370 个真幻觉，比 random 组的约 2,210 个多约 160 个，约 +7%；
- 同时误报约 440 个，比 random 组的约 240 个多约 200 个；
- 修正后的精确率：critic 组约 0.85，random 组约 0.90。

挑难样本带来的变化，相当于把检测阈值调松了一档，没有带来更强的识别能力。

## 7.7 critic 循环迭代实验（2026-10-27 启动，先跑 3 轮）

**目标**：在两条序列上看这种循环什么时候收敛、收敛后的效果，以及「挑难样本」在多轮累积后有没有价值。用户确认先跑 3 轮，看完结果再决定是否跑到 5 轮。

**设置**
- **合成池**：每轮一个新的合成池，两条序列共用。
  - r1：直接用已有的 1,837 对。
  - r2、r3：重新合成，每轮 3,000 个种子，不重复之前改过的「回答 + 句子」。按 source 整体排除会不够用：第 1 轮已经用掉了 1,310 个 source，而全对回答对应的 source 只有约 2,080 个。
  - 每个池都再过一遍 **35B 全文核对**（`ragtruth/fulltext.py`），专门剔除「改动的内容其实在原文别处有依据」的假错误。这一步对两条序列相同，不是对比变量。
- **每轮做法**：用本序列当前的 critic 判断识破率（第 1 轮用 9B v2），然后选样本：
  - random 序列：随机取 600 对；
  - critic 序列：难样本与易样本按 1:1 取 600 对；难样本不够时全部取用，其余用易样本补足。比例固定，不做优化。
- **训练**：v2 基础数据（1:3）加上本序列各轮累积选中的样本，每轮都从基座重新训练。本轮训出的模型作为下一轮的 critic。
- **分工**：主实例负责合成池和 critic 序列，加开的一台机器负责 random 序列，合成池通过内网从主实例拉取。
- **每轮记录**：召回（分任务、分生成模型）、合成池的难样本率、所选样本中难样本的数量。精确率抽检需要用户同意。
- **收敛判据**：连续 2 轮召回增量都小于约 0.01，或者难样本率低于 5%。

**第 1 轮结果**（2026-10-27）

| 9B | 句子级 P / R / F1 | 回答级 R | 召回：数据转文本 / 问答 / 摘要 | GPT-3.5 / GPT-4 召回 | 标为幻觉的比例 | 用本轮 critic 判 r2 池的难样本率 |
|---|---|---|---|---|---|---|
| 基线 v2 | 0.508 / 0.803 / 0.623 | 0.906 | 0.85 / 0.72 / 0.71 | 0.58 / 0.68 | 11.7% | 判 r1 池为 20% |
| random r1 | 0.499 / 0.821 / 0.620 | 0.917 | 0.86 / 0.76 / 0.75 | 0.54 / 0.66 | 12.2% | 10.0%（164/1,639） |
| critic r1 | 0.477 / 0.824 / 0.604 | 0.933 | 0.85 / 0.77 / 0.76 | 0.52 / 0.73 | 12.8% | 7.0%（115/1,639） |

- critic r1 与 random r1 的句子级召回差 +0.004，95% 区间 [−0.010, +0.017]，没有差别。critic r1 的回答级召回高 0.016，GPT-4 回答上的召回高 0.07，但精确率低 0.02。
- 训练一轮之后，下一轮池子的难样本率从 20% 降到 7–10%，用难样本训练的 critic 降得更多。

**第 2 轮结果**（2026-10-27）

| 9B | 累积加入的合成样本 | 句子级 P / R / F1 | 回答级 R | 召回：数据转文本 / 问答 / 摘要 | GPT-3.5 / GPT-4 召回 | 标为幻觉的比例 | 下一轮池子的难样本率 |
|---|---|---|---|---|---|---|---|
| random r2 | 1,200 对 | 0.491 / 0.831 / 0.617 | 0.933 | 0.87 / 0.75 / 0.78 | 0.60 / 0.73 | 12.5% | r3 池 8.0% |
| critic r2 | 1,200 对（本轮挑中的难样本只有 115 对） | 0.463 / 0.826 / 0.594 | 0.925 | 0.86 / 0.75 / 0.77 | 0.54 / 0.68 | 13.2% | r3 池 5.5% |

- critic r2 与 random r2 的句子级召回差 −0.005，95% 区间 [−0.018, +0.009]。
- critic 序列从第 1 轮到第 2 轮召回只增加了 +0.002，已经收敛；精确率继续下降（0.477 → 0.463），标为幻觉的比例继续上升。
- random 序列第 2 轮仍有 +0.010 的增幅。

**迭代实验在第 3 轮中途停止**（用户决定，2026-10-27）。前两轮的结果已经足够说明收敛：critic 序列在第 2 轮就不再提升，所以把资源转到生成器 DPO。r3 池和两条序列在 r3 上的识破率结果都保留着，可以作为难样本示例池。

## 7.8 生成器优化：真实性判别器 + DPO（2026-10-27 启动）

**思路**（与用户讨论后确定）：类似 GAN，但文本无法把梯度回传给生成器，所以改用 DPO 来传递偏好信号。
- 四个角色：
  - 生成器 G：9B + LoRA；
  - critic C：给出难度 h = 1 − 识破率；
  - 真实性判别器 D：9B，给出 p(自然错误)；
  - 有效性门槛 V：35B 复核 + 全文核对。
- 偏好对的构造：无效样本永远只做 rejected；在有效样本里，只用两个维度都更好的样本组对（帕累托占优，两维提升之和 ≥ 0.5）。
- 每轮 G 采样 → 打分 → DPO 更新 G → 用 G 的新输出重训 D → 把「有效、难、像真实」的样本加给 C。
- 停止条件：D 的准确率降到约 55%，或 G 的有效率下降，或 C 在真实测试集上不再提升。

**判别器 D**（`ragtruth/discrim.py`，`configs/rt/discrim_9b.yaml`）
- 数据：自然错误为 RAGTruth 训练集中人工标出的幻觉句，合成错误为 r1–r3 过了全文核对的改写，两类各 2,776 句，按「任务 × 生成回答的模型」配平。按 source 划分为训练 4,696 / 留出 856。
- 输入：原文 + 目标句 + 前后各一句（不给整条回答，防止它利用「回答里别处有没有错」这条捷径）。
- 注意：自然错误中 baseless 占 66%，合成错误中 conflict / baseless 约各一半，分析时要按类型拆开。

**生成器采样**
- few-shot 除了真实幻觉示例，再加 2 个难样本示例（用户建议）：从被较强 critic 漏检、并且过了全文核对的合成样本里选，改法彼此不同，也不同于本条指定的改法。
- DPO 训练用 600 个种子，每个采样 8 条。用户提示偏好对不需要多。

**偏好对的 prompt**：标准 DPO 要求 chosen 和 rejected 共用同一个 prompt，否则推导中的 log Z(x) 无法相减抵消。采样时每个种子分 4 组，每组重新抽示例（3 个真实幻觉 + 2 个难样本，用户建议示例每次都换）。偏好对有两种组法：
- 组内配对：用该组自己的 prompt；
- 统一 prompt 配对：去掉难样本示例段，在同一种子的所有组之间配对，相当于把示例的引导效果蒸馏进参数。用户同意两种都做；用统一 prompt 训练的生成器，评测时也不带难样本示例。

**对照组**
- A：原始 G + 随机选样；
- B：原始 G + 按「难 + 像真实」筛选；
- C：只用难度做 DPO；
- D：用难度 + 真实性做 DPO；
- 另有 in-context 对照：只加难样本示例、不训练生成器。
- 核心指标：真实测试集上的召回提升 Δreal 对比合成难例上的提升 Δsyn。

**判别器 D1 留出集结果**（2026-10-27，856 句，采样 4 次计票打分）

| | AUC | 准确率 | ECE | 平均 p(自然)：自然 / 合成 |
|---|---|---|---|---|
| 全部 | 0.926 | 0.897 | 0.075 | 0.862 / 0.106 |
| conflict | 0.900 | 0.867 | 0.090 | 0.800 / 0.104 |
| baseless | 0.937 | 0.919 | 0.073 | 0.892 / 0.109 |

- 合成错误和模型自然犯的错**很容易区分**，准确率约 90%。所以「真实性」是一个有效的优化信号，合成数据与真实错误的分布差距确实存在。
- 按改法看，合成错误的平均 p(自然) 从高到低：加看似合理的常识 0.28、加结论或概括 0.18、改实体 0.14、改数字 0.13、改否定 0.13、加评价 0.12 …… 调换主客体 0.05、加原因或动机 0.04、加具体细节 0.04、改日期 0.02。
- 交叉对照 §7.3：「调换主客体」「加原因或动机」对 critic 很难，但看起来最不像真实错误，正是「为错而错」的典型；「加结论或概括」「加看似合理的常识」既难又相对像真实错误，与 RAGTruth-Enhance 新增漏标中「概括」「把推断当事实」类占比高相吻合。

## 7.9 生成器—判别器—critic 两轮循环（2026-10-27 夜间启动，`scripts/remote/run_gan.sh`）

**交付物**（用户明确要求）：两轮之后的生成器 G2、判别器 D2、critic C2。为了省钱，其余附加实验一律砍掉：不做分类头判别器对比，不做额外的留出评测组。跑完后保存数据和模型，所有机器关机。

**每一轮**
1. 当前 G 采样：600 个种子，每个 8 条，分 4 组，每组换示例。第 1 轮带难样本示例；从 G1 开始只用统一 prompt。
2. 35B 判有效。
3. 当前 critic 打难度。
4. 当前判别器打真实性（标签词 logprob 的连续分数）。
5. 按难度和真实性两维取帕累托占优构造偏好对（统一 prompt），做 DPO，从上一轮的 G 继续训练。
6. 本轮「难度 + 真实性」得分最高的 600 条（每个种子最多 1 条）累积加入 critic 训练集，critic 从基座重训，在真实测试集上评测。

## 7.10 用真实幻觉句 SFT 生成器（2026-10-28 启动，`ragtruth/realgen.py`、`scripts/remote/run_realgen.sh`）

**动机**：GAN 两轮里 DPO 几乎没学到东西（loss 0.692），D2 给 G1 产出的真实性分数只有 0.028。生成器只靠 13 种改法造错，起点不在真实分布上，DPO 只能在它已经会写的东西里挑。所以先用 SFT 让它模仿真实模型怎么出错。

**数据**
- 来源：RAGTruth 训练集中没有粗粒度句的回答，共 6,221 条，含 10,689 句幻觉句。
- 抽样：用户要求「一千多条就够，但每种都要有」。按（任务类型 × 生成回答的模型 × 错误类型）分成 36 层，轮流抽回答，直到幻觉句达到 2,200 句。每层 18–123 句；一条回答里的幻觉句全部都修。
- 35B 修复：只改标注片段，其余不动；同时写出生成器输出 JSON 的其余字段，并把改法归入 13 类之一。校验和复核沿用合成流程，人工标注的类型为准。
- 抽查：先修 300 句，用 Claude 抽查 30 条（修复句是否有依据、是否最小改动、错误是否还在、证据和说明是否正确），通过后才 SFT。
- SFT 样本：输入是修复后的整条回答，配生成器的统一 prompt（3 个真实示例，示例不用同一原文）；输出是真实错句和分析 JSON。按原文切 15% 留出；约 4k token 以上的样本直接丢掉，不截断。

**修复质量（Claude 抽查，每次 30 条）**

| 版本 | 35B 合格率 | Claude 全部合格 | 修复句有依据 | 最小改动 | 错误仍在 | 证据和说明正确 |
|---|---|---|---|---|---|---|
| v1：只改标注片段，不开思考 | 52% | 53% | 73% | 83% | 90% | 90% |
| v3：同一句里漏标的问题一起修，序号和引用不动，长度规则放宽，不开思考 | 67% | **80%** | 87% | 93% | 100% | 100% |

- v1 的主要问题是 RAGTruth 漏标：同一句里还有没标出的问题，修复句里留着，35B 复核也查不出来。
- v2 开了思考：合格率 62%，但每句约 1.9 万 token，修 2,200 句要 6 小时。用户决定以跑通流程为主，不开思考，只跑了 145 句（保存为 `repair_v2_think.jsonl`）。
- v3 达到 80%，放行 SFT。剩下的问题主要是修复句里仍有少量没依据的措辞（如 "highly rated"），以及个别修复改了句子结构。

**评测**：G0、G2、G_sft 在同一批 300 个新种子上各采样 4 条，比较有效率、D1 真实性分数（主指标）、D2 真实性分数（参考）、C2 下的难样本比例。D2 训练时把 G0/G1 的产出当假样本见过，用它比较会偏向 G_sft，所以以 D1 为准。

**后续**：以 G_sft 为起点做 DPO，学习率从 5e-6 提到约 5e-5。5e-6 是全参数微调的量级，对 LoRA 偏低，可能是 GAN 两轮 DPO 学不动的原因之一。

## 7.6 下一阶段：预判与实验设计（2026-10-27，在结果出来前写下）

完整版见 Claude 文档「实验记录」中的同名章节。要点如下：
- **预判**：
  - 一轮里挑难样本：9B 上比同等条数的随机样本召回高 0.01–0.03，主要提升在 baseless 和摘要；0.6B 上基本没有差别。
  - 迭代：第 2 轮的增益约为第 1 轮的一半，第 3 轮接近 0 甚至变差。
  - 迭代的边界有三条，哪条先到就停在哪：噪声边界（难样本中有效样本 < 50%）、生成器边界（难样本率趋于 0）、分布与测量边界（按人工标签算的召回停在 0.85–0.9 左右）。
- **验证**：
  - V1：9B 的 critic 组和 random 组各多跑 2 个训练种子；另外做一个约 200 条、经 Claude 确认的合成难例测试集。
  - V2：在 9B 上迭代 3 轮。每轮用新的 source；随机累积作为对照；按上面的边界条件决定何时停；可选分支是让 35B 根据 critic 反馈改写样本。
- **生成器 DPO**：
  - 偏好顺序：有效且 critic 识破不了 > 有效但被识破 > 无效。无效样本必须放在 rejected 一侧，否则会出现奖励投机。
  - 先在 9B 生成器上做 LoRA-DPO（A800 更稳），验证有效后再换成 35B（需要 A800 80GB）。

## 9. 踩过的坑

### 9.1 训练与评测
| 现象 | 原因 | 处理 |
|---|---|---|
| 本地 SFT 很慢 | nohup 和后台任务各启动了一次，两个训练进程抢 GPU | 杀掉重复的进程，启动前先查进程 |
| 显存溢出到共享内存、极慢 | Base 模型配合完整 logits 的 NLL | 改用 Qwen3-0.6B instruct 和分块 NLL，batch 4 |
| `drop_overlong` 报错 | transformers 5 里 `apply_chat_template` 返回 BatchEncoding | 加 `return_dict=False` |
| Qwen3.5-9B 训练 OOM | 缺线性注意力 kernel；eval 模式关掉了梯度检查点 | 装 flash-linear-attention；调用 `peft.train()` |
| TRL 报 "expected device meta" | TRL 把权重加载到 meta 设备 | `model_init_kwargs: {dtype: bfloat16, device_map: cuda}` |
| vLLM 加载 9B 权重失败 | 合并后的权重缺 chat template 和 preprocessor 配置；被当成多模态模型 | 从基座复制分词器和处理器文件；加 `--limit-mm-per-prompt '{"image":0,"video":0}'` |
| Windows 访问 WSL 端口时评测挂住 | WSL 端口转发不稳定，请求挂起不报错 | 评测客户端放到 vLLM 容器里跑；客户端超时设 120 s |
| vLLM 前缀缓存命中约 0% | Qwen3.5 混合注意力 | 待查 |

### 9.2 补写与合成
| 现象 | 原因 | 处理 |
|---|---|---|
| 补写通过率低（57%） | 整条回答一起取舍；证据只差标点也算失败 | 改为逐句取舍；rapidfuzz 修正证据；比对时归一化引号 |
| 一致性规则误判很多（620 句） | 「原文没有」和「对照措辞」混在同一条规则里 | 拆成 NEGATIVE 和 CONTRAST 两条；排除「无事实内容」和「without adding unsupported…」 |
| 35B 乱标 disputed | 它同意的句子也标 disputed | 只在理由确实与真值相反时才采纳 |
| 理由里泄露了「ground truth」 | 补写模型照抄提示 | 把这类词加入 LABEL_WORDS |
| 重试后反而输出坏 JSON | 重试时温度更高 | 保留问题最少的那次结果 |
| 合成复核只留下 39% | 「是否自然」的判断不可靠：复核模型看出哪句被改过，就倾向于说它不自然 | 不再按「自然」过滤，只记录；通过率升到 70% |
| 9B 难样本里 30% 无效 | 35B 只看原句对应的那段，没发现别处已经有这条信息 | 待定（小规模清洗 / 合成时让模型核对全文） |

### 9.3 AutoDL 和远程操作

|---|---|---|
| Pro API 创建实例报「无当前资源访问权限」 | 账号权限（实名认证、换 token 都没用） | 改用网页会话接口（`scripts/autodl_web.py`） |

| SFTP 写不进数据盘 | AutoDL 的限制 | 先传到 /root，再 mv |
| pip 很慢 | 阿里云镜像慢 | 测速后换华为云镜像 |
| `pkill -f` 把自己也杀了 | 命令行里包含了要匹配的字符串 | 用 `[p]attern` 的写法；**停止和重启分成两次调用**（2026-10-27，自己的重启命令里带着脚本路径，被同一条命令里的 pkill 匹配到） |

| e5 和 e5b 训练 OOM | 上一组评测完没关 vLLM，它占着 28.6 GB | 每组评测完立即 `pkill vllm` |

| D2 训完，保存时报 `No space left on device`，GPU 空转约 1 小时 | 主实例数据盘 200 GB 被各实验的合并权重（每个 18 GB）占满 | 经用户同意，把 4 个后续用不到的模型（D1、C1、迭代 critic r1/r2）的合并权重删掉，只留 LoRA 适配器（随时可合并恢复）；新增 `train.merge_lora`，从已保存的适配器直接合并，不用重训 |

### 9.4 方法上的坑
- **用人工标签算精确率，会系统性低估更严格的 critic**：RAGTruth 漏标多（§3、§6）。比较实验时召回按人工标签算，精确率要用 Claude 抽查修正。
- **单方面修正标签会偏乐观**：只用 35B 复核分歧句，等于默认 35B 是对的（§3）。
- **训练集的正负比例本身就是一个变量**：直接加入合成数据会同时改变比例（§7.5）。对照组必须控制条数和比例相同，所以要有 random 组。
- **critic 越强，「它识破不了的样本」里噪声越多**（§7.4）。
