# 奖励函数设计

项目里有两个用 GRPO 训的模型：RAG 回答模型和错误生成器。它们的奖励都由几个"单字母打分模型"组合而成。本页写的是现在代码里实际在用的版本：每一项怎么算、参数取多少、为什么这么设计。各版本的对比数据在 [experiments.md](experiments.md)，训练器本身的实现见文末。

## 打分模型

所有打分模型都是 MiniCPM5-2B + LoRA，做成"单字母选项"：给定输入，模型只输出一个字母，我们读这几个字母的 logprob 当概率，再用校准集拟合一个全局温度（`outputs/rt/rm/<名字>/eval/report.json` 里的 `temperature`）。训练配置都是 `configs/rt/rm_mc.yaml`，每个模型的训练数据见 [MODELS.md](MODELS.md)。

| 模型 | 输入 | 选项 | 用到的概率 | 用在哪 |
|---|---|---|---|---|
| critic（rm1__core_*） | 原文 + 回答 + 第 i 句 | A 有依据 / B 与原文矛盾 / C 原文没有（无依据） | P(幻觉) = P(B) + P(C) | RAG 奖励（逐句）；生成器奖励（难度） |
| 满意度 sat_pair__core | 问题 + 两条回答 | 哪条更好 | P_sat：这条回答胜过参考回答的概率 | RAG 奖励（只罚） |
| 拒答 refuse__core | 原文 + 问题 | 能否回答 | P(可以拒答) | RAG 奖励（拒答时） |
| sev（sev__v3c0） | 原文 + 回答 + 原句 / 改写句 + 要求的错误类型 + 逐词改动 | A 要求的那种·显然 / B 要求的那种·细微 / C 别的错 / D 没错 | P(有错) = A + B + C；P(符合要求) = A + B | 生成器门槛 |
| RM2 自然度（rm2__v3b） | 原文 + 回答 + 改写句 | A 自然 / B 不通顺、不合语境或明显是人为改的 | P(自然) = P(A) | 生成器门槛 |
| 9B 金标 critic（rm1__rm1_gold_9b） | 同 critic | 同 critic | — | **只做评测，不进任何奖励** |

## RAG 回答模型：R3 奖励

先说为什么奖励是一个组合，而不是只有 critic。critic 只管"有没有幻觉"，而最省事的降幻觉策略恰恰是不好好回答：全部拒答（critic 对拒答句几乎恒判无错，P ≈ 0.01）、照抄原文、答非所问、越写越短。下面的每一项都对应其中一种：硬规则堵照抄和长度，拒答单独计分堵全部拒答，满意度护栏堵答非所问和写得空洞。它们都只扣分或设上限，不给额外奖励，避免模型转而去钻这些模型自己的空子。

代码：`train/ans_reward.py`（`check`、`group_baseline`、`count_reward`、`sentence_adv`、`guarded`），`train/ans_grpo.py`（`token_advantages`）。

### 第一步：硬规则

不过硬规则的回答直接记 0 分，也不去调 critic。这些规则都不依赖 critic，防的是"不好好答题也能拿分"。

| 规则 | 判定 |
|---|---|
| 空回答 / 被截断 | 没有句子，或生成没正常结束 |
| 长度 | 不在参考长度的 0.5–1.5 倍之间。参考长度是起点模型对同一题采样时，正常结束的回答的中位长度 |
| 照抄原文 | 和原文的重合比例 ≥ 0.9（问答）/ ≥ 0.5（摘要） |
| 没写完 | 结尾不是句末标点 |
| 语言 | 原文是英文，回答里却出现中文 |
| 拒答 | 单独处理，见下 |

### 第二步：整段分 H

critic 对回答的每一句给出 P(幻觉) p_i。直接把它们加起来会出问题：critic 对没错的句子也有底噪（平均 P 约 0.10，而显然错句的中位数才 0.20），句子越多，累积的底噪越多，结果模型学会少写。所以先去掉底噪：

- b：同一个 prompt 的所有回答、所有句子的平均 P，当底噪；σ 是它们的标准差（下限 0.1）；
- e_i = max(0, p_i − b)：每句超出底噪的部分；
- K = max(2, 0.5 × 参考回答的句数)：参考回答由起点模型重采得到。

```
H = 1 − 0.5 × (1 − Π_i (1 − e_i)) − 0.5 × min(1, Σ_i e_i / K)
```

前一半是"至少有一句错"的概率，后一半是按错句数计数。这样一句错和两句错的分数不一样，而正确的句子（p ≈ b）多写不扣分。

### 第三步：满意度护栏和拒答

```
r = max(0, H − 0.8 × max(0, 0.5 − P_sat))       # 满意度低于 0.5 才扣，最多扣 0.4；只罚不奖
拒答：r = 0.4 × P(可以拒答)                      # 最高 0.4，比一般的好回答低
```

满意度只罚不奖，是为了防止模型为了避开幻觉，把回答写得空洞、答非所问；但它又不能当正向目标，否则会被钻空子。MiniCPM 本来就偏爱拒答，所以拒答最多只给 0.4，并且要原文确实答不了才拿得到。

### 第四步：优势值（句子级）

```
整段优势 A = (r − 组均值) / 组标准差                       # 同一 prompt 的 16 条回答；全组奖励相同则为 0
句子优势 a_i = −e_i / σ                                    # 只罚超出底噪的句子，其余为 0
a_i += 0.3 × min(0, a_{i+1})                               # 后一句的负值按 γ = 0.3 传给前一句（只传一步）
第 i 句每个 token 的优势 = A + 0.6 × a_i                   # β = 0.6
```

句子优势只加在出错那一句的 token 上。这一步是整个奖励里最关键的：R0（整段一个分）和 R1（整段去底噪计数）效果几乎一样，加上句子层（R2）之后，显然错句数才明显下降，再往前传一句（R3）又好一些（[experiments.md §7.4](experiments.md)，技术分享详细版表 1）。没超出底噪的句子不给正奖励，因为那样会鼓励多写安全的废话。

### 训练设置

| 项 | 取值 |
|---|---|
| 每步 | 16 个原文 × 每个 16 条回答，采样温度 1.0、top_p 1（不截断，和策略梯度的假设一致） |
| 学习率 / 步数 | 5e-6；每段 100 步（第一段 200 步） |
| 损失 | PPO 截断（0.2）− 0.05 × KL（k3 估计，相对本段起点） |
| 异步 | 采样最多比训练领先 2 个版本，比值里的旧概率用采样时的值 |
| TripWire | 第 45 步起，最近 20 步和第 6–25 步比：长度掉到 0.75 倍以下或涨到 1.3 倍以上、照抄比例 +0.15、拒答 +0.05、通过硬规则比例 −0.15、KL ≥ 0.1，任一项越线就存档并停下 |

命令：`scripts/remote/run_r3full.sh`。各段起点、critic 和数据见 [MODELS.md](MODELS.md)。

## 错误生成器：门槛 + critic 难度

代码：`train/gen_reward_v2.py`（`V2SevRewarder`，`--reward v2sev --v2_shape hard`），`ragtruth/gen_v2.py`（输出格式和解析）。

生成器的输入是原文、一条回答（其中的句子都是 critic 判为干净的）和一种要求的错误类型（9 选 1，见 README 的错误体系）。它输出 JSON：`{"idx": 第几句, "sentence": 改写后的句子, "edit": 改了什么}`。目标是造出 **真错、读着自然、critic 拿不准** 的句子。

### 硬规则（0 分）

解析不出 JSON；句号越界；改写句和原句相同，或者照抄回答里另一句；改写句比原句长 3 倍以上并且多出 300 字符以上（在一句里塞好几个错）；出现 hallucination、faithful、the source、source text、not stated in、error 之类点破题目的词。

### 门槛和难度

```
门槛：sev P(有错) ≥ 0.9  且  RM2 P(自然) ≥ 0.5           # 没过门槛：0 分
h(p) = 0              p < 0.1        # critic 完全看不出：多半不是真错
     = (p − 0.1)/0.2  0.1 ≤ p < 0.3
     = 1              0.3 ≤ p < 0.5  # critic 拿不准：最想要的样本
     = (0.9 − p)/0.4  0.5 ≤ p < 0.9
     = 0              p ≥ 0.9        # critic 一眼看出：没用
r = h(critic P(幻觉))                 # critic 用 rm1__core_r2
```

优势值是同一 prompt 的组内归一化：同一 prompt 只要求一种类型，所以就是减组均值、除以组标准差。每步 8 个 prompt × 32 条，学习率 5e-6，50 步。提示按类型加权：critic 弱、又造得出难样本的四类（范围偏移、近义偏移、跨段拼接、张冠李戴）多放一倍，造难之后就变成别的类型的那两类少放（`scripts/make_prompts_w.py`）。

### 为什么是这个形状

- **不单调地奖励"骗过 critic"。** 第一次尝试（gated 版）是直接奖励 critic 判不出的样本，结果模型学会造 sev 也会误判的"非错句"，真错只剩 24%。critic 完全看不出的（P < 0.1）大多本来就不是错，所以 h 在两头都是 0。
- **过门槛不设保底分。** 加了 0.1 的保底（h1）以后，明显错的样本比没过门槛的更划算，模型反而往 P ≥ 0.9 跑（占比从 55% 涨到 72%）。去掉保底才方向正确。
- **sev 门槛取 0.9。** sev 在 0.5 时只有约 55% 是真错，0.9 时约 85%。代价是门槛很严：后来发现 sev 和 critic 在同一批句子上一样拿不准，大量 critic 盲区的真错被这道门槛挡掉了（[experiments.md §5.12](experiments.md)）。

### 这个奖励的实际效果

坦白说，GRPO 在这里只起了一部分作用。过门槛样本里只有约 5% 落在 0.1–0.5，大多数组内的样本都在 0.7 以上、奖励几乎相同，信号太稀，50 步在留出提示上几乎看不出变化。后来真正管用的是"采样 → 挑难样本 → SFT"的迭代，GRPO（g1）只是其中一轮。生成器各版本的数据见技术分享详细版表 5、表 6。

### 做过但没采用的变体

| 变体 | 参数 | 结果 |
|---|---|---|
| sev 奖励：r = P(符合要求) | `--v2_shape sev` | 真合格产出约 ×5，但多数是 critic 已经能判出的错 |
| 三角 + 保底 0.1（h1） | `--hard_base 0.1` | 往明显错跑，见上 |
| 只奖励 < 0.7（h2） | `--hard_shape low` | 同样受信号太稀所限，没有采用 |
| 组内排名 + 三角各一半 | `--hard_shape rank` | 强化的是"过门槛"而不是"更难"，0.1–0.5 的条数没变 |
| critic 区间当门槛 | `--crit` | 几乎没有正样本，学不起来 |

### 第一代生成器的奖励（已弃用）

核心集之前的生成器用的是另一套：9B 打分模型、RM3 判"合格"，按 4p(1−p) 给难度，再加真实性和多样性三项平均。这套奖励被模型钻过空子：它会编造新的"改法"名字来骗多样性分。后来整条生成器路线都换成了现在的 v2。过程见 [experiments.md §5.6、§5.8](experiments.md)。

## 训练器

两个 GRPO 都用项目自己写的训练器（`train/gen_grpo.py`，RAG 版在 `train/ans_grpo.py` 复用它的训练步）：vLLM 采样并同时挂着打分 LoRA，策略 LoRA 每步热加载；HF + PEFT 训练；同一 prompt 的多条回答共享 prompt 前向（`train/prefix_share_llama.py`）。正确性检查：前缀共享和整段拼接的 logprob、梯度对比（`tests/test_prefix_share_llama.py`）；训练日志里的 `vllm_hf_absdiff`（采样侧和训练侧的逐 token logprob 差，正常约 0.01）和 `staleness`。
