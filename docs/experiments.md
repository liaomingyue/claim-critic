- [prompts.md](prompts.md)：所有提示词原文；[gold_standard.md](gold_standard.md)：金标标注规范。

**怎么读。** 项目大致经历了三个阶段，模型和评测集都换过，比较数字时要注意属于哪个阶段：

1. **RAGTruth 标签阶段**：critic 用 Qwen3-0.6B 和 Qwen3.5-9B，训练数据以 RAGTruth 人工标注为主，Qwen3.5-35B 负责补写、合成和判有效。这一阶段弄清了标签噪声、输出格式和「挑难样本」这几件事。
2. **全 2B 阶段**：所有进训练、进奖励的模型换成 MiniCPM5-2B + LoRA，critic 改成单字母分类；9B 金标 critic 只当评测器。这一阶段建立了 RAG GRPO 的奖励形式，做了大量「critic 该用什么数据」的对照。
3. **核心集与闭环阶段**：数据起点换成「2B 自己写的回答 + Claude 逐句改对」的核心集，在此基础上完成了 RAG 分段强化和两轮盲区驱动闭环。

后面的阶段经常修正前面的结论。遇到这种情况，正文给出最终的理解，并说明一开始是怎么以为的、后来是什么实验改变了看法。

### 1.1 模型与缩写

| 缩写 | 含义 |
|---|---|

| 9B | Qwen3.5-9B + LoRA。早期是 critic 和生成器的主力，后来只用来做不进训练的评测和监控 |
| 35B | Qwen3.5-35B-A3B-GPTQ-Int4，早期用于补写理由、合成错误、判有效 |

| RM3 | 合成错误正确性判别器：合格 / 解释不对 / 其实没改出错 / 原句本身有错 |
| sev | 严重程度判别器，几代选项不同（见 §5.7、§5.10、§5.11） |
| 9B 金标 critic | `rm1__rm1_gold_9b`，9B 底座，用 RAGTruth 人工标注、Claude 金标和 9B 自己的回答训练（§4.5），后期所有 RAG 评测都用它打分 |

### 1.3 指标

- **句子级 / 回答级**：早期按 hallucination 类算句子级 P / R / F1，不计粗粒度句；回答里只要有一句判为幻觉，整条回答算幻觉，与 RAGTruth 论文的 response-level 一致。
- **显然错 AUC**：cap3 上「显然错 vs 没错」的 AUC，是后期 critic 的主口径，同时报误报 10% 时的召回。「任意错」口径把轻微错也算进去。
- **判出同样多条时的召回**（same-flag）：把被比较的两个模型调到判出同样多句，再比召回，用来排除阈值漂移带来的虚假提升。
- **RAG 显然错**：9B 金标 critic 逐句打分，P ≥ 0.9 记为显然错，P ≥ 0.5 记为任意错。这只是近似：在 Claude 标注集上，P ≥ 0.9 这一段约 64% 是显然错，召回约 42%。主指标是「每条回答的显然错句数」和「含显然错的回答比例」。
- **区间**：早期 9B 实验是按回答 bootstrap 的 95% 区间；从金标评测开始改为按原文聚类 bootstrap（同一原文的多条回答相关，按回答抽样区间偏窄，按原文抽样约宽 1.1 倍），后期统一用 90% 区间。各表沿用原始计算时的口径，表旁注明。
- **严格口径**：边界不明确的按有错处理。含糊的评价、目的附加语，改变语气或确定性的近义替换都算错，只有意思完全不变的改写才不算；拿不准时判为有错。这样定是因为 critic 要学的正是这些细边界，宽松口径会把它们教成「没错」。Claude 和各判别器从这时起共用同一份定义。
- **以召回为主**：RAGTruth 人工标签漏标多，按人工标签算的精确率会系统性低估更严格的 critic，所以评价以召回为主，精确率只用 Claude 修正后的标签估计。

### 1.5 9B 评测器和 Claude 的一致性

所有 RAG 的"含显然错 / 含任意错"比例都由 9B 金标 critic 打分。它和最终的人工判断（这里用 Claude 代替）一致到什么程度，我们在六组都有 Claude 逐句金标的回答上检验，共 3,839 句。口径和 RAG 评测完全一致：9B 有一句 P ≥ 0.9 记"含显然错"，有一句 ≥ 0.5 记"含任意错"。

| 组 | 句子级 AUC（显然错 / 任意错） | 含显然错：9B / Claude，一致率，κ | 含任意错：9B / Claude，一致率，κ |
|---|---|---|---|
| 9B 原始 | 0.902 / 0.861 | 35.7% / 44.9%，74.5%，0.47 | 63.3% / 75.5%，77.6%，0.48 |
| 9B GRPO | 0.958 / 0.843 | 22.0% / 20.0%，82.0%，0.46 | 45.0% / 64.0%，67.0%，0.36 |
| 2B 基线 | 0.923 / 0.851 | 43.0% / 43.0%，80.0%，0.59 | 51.0% / 70.0%，73.0%，0.46 |
| 2B GRPO（验收 a） | 0.939 / 0.857 | 20.0% / 25.0%，95.0%，0.86 | 30.0% / 52.0%，78.0%，0.57 |
| 2B GRPO（验收 b） | 0.804 / 0.784 | 14.0% / 33.0%，71.0%，0.23 | 34.0% / 61.0%，69.0%，0.42 |
| 2B GRPO（验收 c） | 0.803 / 0.802 | 19.4% / 34.1%，75.3%，0.39 | 33.6% / 64.9%，65.2%，0.37 |
| **2B GRPO 三套合并** | **0.822 / 0.807** | **18.6% / 32.4%，77.9%，0.43** | **33.1% / 62.1%，68.0%，0.41** |

2B GRPO 三套合并（596 条回答）最接近实际的 RAG 评测场景：RAG 各版本就是在这三套原文上重新生成、再由 9B 打分的。

比较两个模型时，9B 和 Claude 各自算出的差值（同一批原文-种子配对）：

| 比较 | 含显然错：9B / Claude | 含任意错：9B / Claude |
|---|---|---|
| 9B 原始 → 9B GRPO | −14.3 / −24.5 | −19.4 / −12.2 |
| 2B 基线 → 2B GRPO | −23.0 / −18.0 | −21.0 / −18.0 |
| 9B GRPO vs 2B GRPO | −2.0 / +5.0（方向相反，两边都不显著） | −15.0 / −12.0 |

结论：
- **训练前后的大变化，9B 和 Claude 方向一致、幅度相近。** 这是我们用 9B 做评测最主要的依据。
- **在 RL 训练后的输出上，9B 只是中等可靠。** 2B GRPO 三套合并：句子级显然错 AUC 0.822，回答级"含显然错"κ 0.43。同一批句子上，我们最好的 2B critic（r2）AUC 是 0.872，也就是说 9B 评测器在这类输出上并不比被评测的 critic 更准。RL 训练后剩下的错，本来就偏向 critic 看不见的类型，9B 和 2B critic 用的是同源数据，也会一起变弱。
- **绝对比例偏低。** 9B 报的"含显然错"约为 Claude 的六成（18.6% vs 32.4%），"含任意错"约为一半（33.1% vs 62.1%）。文中所有比例都只能当 9B 口径的相对变化看，不代表真实错误率。
- **几个点的小差距，方向没有保证。** 闭环的关键对照（新 critic 比对照少 2–3 个点含显然错）正落在这个区间。它在 9B 口径下两次独立运行都显著，但没有用 Claude 直接验证过方向。
- 一个混杂因素：验收 a 和前四组是一条回答一次调用标注的，验收 b、c 是同一原文的 3 条回答一次调用批量标注的。a 用温度 1.0 采样，按理错误更多，9B 也这么认为（20% vs b 14%），Claude 却给 b、c 标出了更多显然错（33–34% vs 25%）。批量标注可能更严，这会放大 b、c 上的分歧，但现有数据分不开这两个因素。

代码：`scripts/analysis/eval9b_agreement.py`、`scripts/remote/run_eval9b_agree.sh`（给验收 b、c 补 9B 打分）；结果：`results/eval9b_agreement.json`。

## 2. 数据与金标

### 2.1 RAGTruth 转换与补写理由

RAGTruth 的回答按句切分，与人工标注片段重叠 ≥ 3 个字符的句子记为幻觉，类型分 conflict 和 baseless。一个标注片段覆盖 ≥ 3 句时，标注员显然是整段划的，句子级标签不可信，这些「粗粒度句」不作训练样本也不计指标（测试集 147 句）。训练只用 1/10（`train_sub`，按 source 取，1,410 条回答），其余 `train_pool` 当合成种子。

人工标注只有片段、类型和简短备注。为了训练「先写证据再写理由」格式的 critic，我们把真值交给较大的模型，让它为每句写出逐字证据和不含结论词的理由，并校验证据可定位、理由与真值一致。补写模型从本地 9B-Q4 换成 35B 并加一致性校验后，0.6B 和 9B critic 的 F1 都提升约 0.03。产物是 `train_sub35_r3.jsonl`（3,484 条，幻觉 : 无幻觉 = 1:3）和 `train_sub35_nat.jsonl`（8,298 条，自然比例约 8%）。

代码：`ragtruth/convert.py`、`annotate.py`、`build.py`。

### 2.2 人工标签有多可靠

这一组实验贯穿全项目：标签口径和标签噪声是影响最大的变量。

**35B 全量复核 + Claude 仲裁。** 0.6B critic 误报很多，我们想先弄清是模型问题还是标签问题。35B 独立判断测试集每一句，和人工一致率 79.4%；35B 判出 26.8% 的句子有幻觉，人工只标了 7.5%。分歧句交给看不到双方判定的 Claude 裁定：「35B 判有、人工判无」60 句中 Claude 同意 35B 的 35 句；「人工判有、35B 判无」20 句中同意人工的 16 句。结论是**人工标为有幻觉的基本可靠，标为无幻觉的漏标严重**；而只用 35B 单方面修正会偏乐观，因为 35B 自己也误报很多。

**RAGTruth++ 的佐证。** 用 ++ 的 402 条回答量化：原标注的 87 个幻觉句 ++ 全部保留；原标注无幻觉的 2,199 句里 ++ 判出 542 句有幻觉（24.6%）；原标注全对的 337 条回答里 236 条至少有一句幻觉。

**++ 新增的 542 句也不全算数。** 人工对照原文读了 40 句，再让 Claude 逐句标全部 542 句：真幻觉 236（43.5%）、轻微 162、吹毛求疵 113、开头报字数的套话 31（例如题目要求 104 词，回答写「Here is a summary in 106 words」）。人工 40 句和 Claude 在「是否有效」上一致 90%。由此定义了 ++ 的「有效」口径：正例 = 原标注 87 句 + real 236 句，其余 306 句不计分。此后同时报严格和有效两套数字。

**训练负例的漏标。** critic 实际训练用的 2,613 个负例按任务分层抽 100 个，混入 20 个正例对照，Claude 盲判：28% 有幻觉（QA 36%、Summary 24%、Data2txt 24%），正例对照 19/20 判为有幻觉，说明 Claude 不偏宽松。漏标集中在本来就有错的回答里（40%），但「全对回答」里也有约 1/5。典型漏标是列表里多出原文没有的项、给原文事实添上目的或方式、把条件或数量说错、张冠李戴。

**测试集负例。** ++ 判无幻觉的句子分层抽 376 句，Claude 按严格口径判出 44 句有幻觉（11.7%，95% 区间约 8.6–15.4%）；原标注幻觉 24 句里 Claude 同意 23 句。

**严格口径下的训练负例。** 后来按严格口径再抽 QA、Summary 的清洗后训练负例 100 句：72 句不是错、24 句轻微、4 句明显，即 28% 有错（QA 17%、Summary 40%），主要是无依据推断、确定性或范围改变、含糊附加语。这和清洗时估的 4.5%（§4.3）不矛盾：后者用的是清洗时较宽的口径。

**A 行藏错。** 2B critic 训练集里标为「有依据」的 3,724 条，按来源抽 220 条 Claude 严格口径盲判：藏错 23 条（10.5%），**全部是轻微错误**。按来源：RAGTruth 人工 11/100、合成里没改的句子 7/40、Claude 金标 2/30、9B 回答 + Claude 单轮 3/50。类型集中在范围夸大（「some reviews」其实一两条）、加评价、去掉不确定性、限定条件丢失。critic 自己很难找出这些藏错：用 P(错) = 1 − P(A) 排序，2B 的 AUC 0.717、9B 0.781，多数藏错分数 < 0.15。

代码与数据：`ragtruth/adjudicate.py`、`arbitrate.py`、`pp_valid.py`、`audit_neg.py`、`audit_test.py`、`miss_analysis.py`；`outputs/rt/analysis/`。

### 2.3 Claude 金标

既然人工标签不可靠，我们决定用 Claude 按一份明确的规范（[gold_standard.md](gold_standard.md) v1，严格口径，区分明显 / 轻微）重新标一批，作为核心种子和核心评测标准。

- **试标**：10 条回答 56 句，每条独立标两遍。是否有错一致 54/56（96.4%），明显 / 轻微一致 54/56。RAGTruth 原标注在这 56 句里只有 2 句正例，和 Claude 结论不同的有 17 句。
- **种子集**：100 条回答 1,011 句，错误 290（明显 168），随机选的 40 条回答里 36 条带错；两遍一致 987 句。
- **测试集**：RAGTruth++ 的 402 条回答各标一遍，错误 705（明显 321、轻微 384），带错回答 324，与 ++ 一致 1,988 句（86.2%）。

金标有两个局限：评测金标只标一遍，且和训练金标是同一模型同一标准，对用金标训练的组可能偏有利；Claude 与真人的一致性没有测过。

代码：`ragtruth/gold.py`；数据 `outputs/rt/gold/`。

### 2.4 核心集

前两个阶段的数据来源很杂：RAGTruth 人工标注、9B 回答、早期合成。核心集阶段我们把数据起点统一成一份：**2B 在 831 个 RAGTruth 训练原文上写的回答（有参考回答的 807 条），由 Claude 逐句改对，并标注错误类型、严重程度和满意度**。这样标签更干净，错误分布也和真正要检测的模型一致。

Claude 只改错句：807 条里 597 条有改动，共 1,680 个改动（显然 723 / 细微 957；矛盾 1,169 / 无依据 511），195 条无误原样保留，15 条不该拒答的整条重写。机制前几位是确定性或范围偏移 325、其他矛盾 267、偷换概念 245、张冠李戴 231、无依据推断 217、添加评价 185。改法都是最小改动，例如 "over 70%" → "as many as 70%"、删掉原文没有的 "peaceful"。

81 个原文留出，其余派生出全部训练数据：D1 RAG SFT、D2 RAG GRPO 原文池（750）、D3 种子错误对（训练 1,472 / 留出 155）、D4 改写提示池、D5 RM2、D6 sev、D7 满意度（4,544）、D8 拒答（1,101）、D9 critic（4,604 行：A 3,194 / B 990 / C 420）。拒答数据的删段门槛定为 0.3，是在旧 Claude 复判的 23 条上最准的值。

种子集本身的质量用 Claude 抽查过：D3 随机 200 条，真错里类型、证据、理由三项全对 92%，「真错且解释全对」约 88%。规则检查上证据逐字在原文 1,336 / 1,338。

代码：`ragtruth/core_label.py`、`ragtruth/core.py`（build / derive）、`scripts/remote/run_core1.sh`；数据见 RELEASE.md 的 `core.tar.gz`。

## 3. critic 早期探索（0.6B / 9B，RAGTruth 标签）

### 3.1 基线与模型规模

先在 0.6B 上跑通「逐句 + 证据 + 理由」格式，再看换大模型、改进补写质量各带来多少。

| 实验 | 设置 | 句子级 P / R / F1 | 回答级 F1 |
|---|---|---|---|
| 零样本 0.6B | 不训练 | 0 / 0 / 0 | 0 |
| 回答级 0.6B | 一次判整条回答，1,410 条，自然比例 | 0.537 / 0.578 / 0.557 | 0.741 |
| 逐句 v1 0.6B | 9B-Q4 补写，1:2 | — / — / 0.434 | 0.626 |
| 逐句 v2 0.6B | 35B 补写 + 校验，1:3 | 0.340 / 0.717 / 0.461 | 0.659 |
| 逐句 v1 9B | 同 v1 数据，LoRA | 0.470 / 0.816 / 0.596 | 0.740 |
| 逐句 v2 9B | 同 v2 数据，LoRA | 0.508 / 0.803 / 0.623 | 0.772 |

模型规模影响最大：同一份数据 9B 比 0.6B 高约 0.16 F1。补写质量对两者都有约 0.03 的帮助。「理由说有问题、判定却说没问题」的不一致是从数据里学来的，加一致性校验后减半。

### 3.2 输出格式拆解

0.6B 上「一次输入、输出很少」的版本看起来更好，于是把粒度、是否写理由、顺序、正负比例拆开比较（0.6B，95% 区间）：

| 编号 | 粒度 | 输出格式 | 数据 | 句子级 P / R / F1 | 回答级 R / F1 |
|---|---|---|---|---|---|
| e2 | 逐句 | 只给 type + verdict | 自然比例 8,298 条 | 0.643 / 0.617 / 0.630 | 0.739 / 0.766 |
| e3 | 逐句 | 证据 → 理由 → type → verdict | 同上 | 0.515 / 0.582 / 0.547 | 0.738 / 0.714 |
| e4 | 逐句 | type → verdict → 证据 → 理由 | 同上 | 0.633 / 0.563 / 0.596 | 0.695 / 0.744 |
| v2 | 逐句 | 证据 → 理由 → type → verdict | 1:3，3,484 条 | 0.340 / 0.717 / 0.461 | 0.875 / 0.659 |
| e5 | 回答级 | 每句一行证据，再列错误句 | 774 条回答 | 0.257 / 0.432 / 0.323 | — / 0.646 |
| e5b | 回答级 | 只列错误句 | 同上 | 0.323 / 0.611 / 0.423 | — / 0.698 |

- 1:3 的比例让精确率从 0.52 跌到 0.34，但召回从 0.58 升到 0.72。改成以召回为主后，这不一定是坏事。
- 把判定放到最前（e4），精确率就回到 e2 的水平，说明「先写理由再下结论」时理由写偏会把结论带偏。但 e4 召回仍比 e2 低 0.054：带证据和理由会稀释判定 token 的学习信号。
- 回答级格式让 0.6B 一次为十几句写证据，F1 掉 0.10，而且对数据量敏感（774 条 0.423，1,410 条 0.557）。

**9B 上情况不同。** 同样的 v2 数据只换格式：只给判定 P/R/F1 0.599 / 0.806 / 0.687，证据 + 理由 0.508 / 0.803 / 0.623。两种格式召回几乎一样，差别只在精确率，而 9B 的误报里 78% 其实是真幻觉（§3.4）。所以 9B 写证据和理由不损失召回，还能给出可核查的解释；0.6B 写理由掉召回是容量问题。对召回来说，训练数据的影响也远大于格式：几种格式召回差 ≤ 0.05，合成数据能把召回提高 0.07–0.09。

### 3.3 e3 为什么比 e2 差

e2、e3 在全部测试句上逐句对比，分歧句分层抽 80 句交 Claude 仲裁。判断在写理由的过程中就做出了：e3 只错的句子里，判定和它自己的理由一致的，漏报中 97%、误报中 76%。理由出错有三类：意译、概括类句子找不到逐字依据就写成「原文没提到」（这是主因，数据转文本最多）；理由本身读错原文（把 JSON 里的 `upscale: False` 读成 True，训练时理由由 35B 写好，测试时 0.6B 自己生成，一处错后面跟着错）；以及一部分「误报」其实是人工漏标。按 Claude 修正标签后，e2 F1 0.630 → 0.651，e3 0.560 → 0.626，**差距从 0.070 缩到 0.025**。也就是说约三分之二的差距来自测试集漏标，剩下的才是格式本身。

代码：`scripts/analyze_e2_e3.py`、`ragtruth/arbitrate_pair.py`。

### 3.4 召回视角与真实精确率

按人工标出的 1,404 个幻觉句算召回（人工判有的基本可靠，召回可信）：9B v2 句子级 0.803、回答级 0.907，分任务数据转文本 0.85 / 问答 0.72 / 摘要 0.71；0.6B v2 为 0.717 / 0.875。

从 9B v2 的 1,063 个误报里抽 60 个交 Claude，47 个（78%）是真幻觉，估算真实精确率 0.895（95% 区间 0.84–0.94），而按人工标签只有 0.515。9B v2 召回 0.80、真实精确率约 0.9，以召回为主已经可用。此后 9B 作主力，0.6B 用于快速验证方法。

代码：`ragtruth/arbitrate_fp.py`。

### 3.5 生成式 critic 换成单字母分类

critic 要当奖励、当难度打分器，需要连续、校准的概率。我们把 critic 改成单字母选项分类（RM1：A 无幻觉 / B 冲突 / C 无依据），校准集上拟合一个全局温度。同一份训练数据（清洗负例 + G_free 合成，§4.3）下：

| | ++ 严格 P / R | ++ 有效 P / R / AUC |
|---|---|---|
| 生成式 critic-clean-gfree | 0.816 / 0.509 | 0.746 / 0.656 / — |
| 生成式，与 RM1 逐句相同的数据重训（critic-rm1same） | 0.814 / 0.466 | 0.753 / 0.632 / — |
| 单字母 RM1（T = 1.3） | 0.890 / 0.512 | 0.849 / 0.674 / 0.945 |

单字母分类召回相当、精确率高约 0.08–0.10。有效口径下概率基本对齐（0–0.1 段实际 3.6%，0.9–1 段 91%）。RM1 给合成样本打的难度和生成式 critic 的识破率 Spearman 0.842（连续概率 0.897），可以代替生成式 critic 打难度，只需一次前向。此后所有 critic 和判别器都用这种格式。

同一个基座挂多个 LoRA 服务（不量化）和合并权重相比，RM1 最可能选项一致 99%、RM3 100%，可以用一个基座 + 多 LoRA 同时提供三个 RM。

代码：`ragtruth/rm_data.py`、`ragtruth/rm_eval.py`、`ragtruth/rm1_cmp.py`、`configs/rt/rm_9b.yaml`。

## 4. critic 该用什么数据

这一章是整个项目的主线问题。结论在几个阶段里被反复修正，最终的理解是：**critic 本来就判得出的错，加多少都没用；有用的是 critic 拿不准、类型落在它盲区、又被人核实过的真实错误；而「当奖励好不好用」不能只看静态指标。**

### 4.1 合成错误 + 挑难样本（0.6B / 9B）

**合成。** 从 `train_pool` 里整条回答没问题的 7,056 条中分层抽 3,000 条，每条挑一句有事实内容的句子，按 13 种改法之一由 35B 改写，同时写出证据和理由；规则校验后再让 35B 把原句和改后句随机排成 A/B 复核。每加一条错误句，同时加入它的原句作为无幻觉样本（成对加入）。3,000 条通过 1,837 条（61%）。复核原本也判「是否自然」，但复核模型一看出哪句被改过就倾向于说不自然，只留下 39%，于是不再按自然度过滤。

**critic 识破率。** 每条错误句采样 4 次，识破率 < 50% 记为难样本。0.6B 平均识破率 0.30、难样本 66%；9B 平均 0.71、难样本 25%，基本是 0.6B 难样本的子集。按改法看，事实替换类（数字、实体、否定、日期）9B 几乎都能识破（难样本 6–12%），推理、归因类仍有 30–50% 识破不了（加原文没有的结论或概括 51%、加原因或动机 39%、调换主客体 34%）。所以「合成错误太简单」对 0.6B 不成立，对 9B 部分成立。

**难样本里有多少是真错。** Claude 抽查：0.6B 难样本 85% 是真幻觉，9B 难样本 70%，被识破的样本 100%。9B 的无效样本几乎都是「35B 以为加了原文没有的信息，其实在原文别处」。**critic 越强，它识破不了的样本里无效样本越多**，「挑 critic 识破不了的」必然顺带挑进标签噪声。

**三组对照。** direct（全部 1,837 对）、critic（只加难样本）、random（随机同样条数），比例和条数严格对齐：

| 9B | 句子级 P / R / F1 | 回答级 R | 标为幻觉比例 |
|---|---|---|---|
| 基线 v2 | 0.508 / 0.803 / 0.623 | 0.906 | 11.7% |
| critic（460 对） | 0.414 / 0.838 / 0.554 | 0.953 | 15.0% |
| random（460 对） | 0.479 / 0.843 / 0.611 | 0.927 | 13.0% |
| direct（1,837 对） | 0.459 / 0.821 / 0.589 | 0.932 | 13.3% |

critic 组减 random 组句子级召回 −0.005（95% 区间 [−0.019, +0.009]）；0.6B 上 +0.008 [−0.012, +0.027]。挑难样本没有带来更多召回，direct 加了 4 倍样本召回也没更高，9B 在约 460 对时就数量饱和了。两组各自多报的句子 Claude 各抽 50 条，都是约一半真幻觉，critic 组只是整体判得更多：修正后真幻觉多找出约 7%，误报多约 200 个，相当于把阈值调松一档。

一开始我们以为「先加合成，再加难样本」会把召回再推高 0.01–0.03，这个预判没有得到支持。

代码：`ragtruth/synth.py`、`mine.py`、`audit_synth.py`。

### 4.2 critic 循环挖难样本

接着看「循环」本身：每轮新合成一个池子，用当前 critic 打识破率，critic 序列按难 : 易 = 1 : 1 选 600 对，random 序列随机选 600 对，累积加入并从基座重训。每个池子先过一遍 35B 全文核对，剔除「改动内容其实在原文别处有依据」的假错误。

| 9B | 累积加入 | 句子级 P / R / F1 | 下一轮池子难样本率 |
|---|---|---|---|
| 基线 v2 | — | 0.508 / 0.803 / 0.623 | 20% |
| random r1 | 600 对 | 0.499 / 0.821 / 0.620 | 10.0% |
| critic r1 | 600 对 | 0.477 / 0.824 / 0.604 | 7.0% |
| random r2 | 1,200 对 | 0.491 / 0.831 / 0.617 | 8.0% |
| critic r2 | 1,200 对 | 0.463 / 0.826 / 0.594 | 5.5% |

critic 序列第 2 轮召回只增 0.002，已经收敛，精确率继续下降；两轮里 critic 和 random 的召回差都在区间内。训练一轮后，下一轮池子的难样本率就从 20% 掉到 7–10%。前两轮已足以说明收敛，第 3 轮中途停止，资源转向改进生成器本身（§5）。

### 4.3 清洗负例 vs 加合成数据

**一开始以为瓶颈在合成数据不够难或不够真，后来发现是负例标签。** §2.2 显示训练负例约 1/4 是漏标的幻觉，critic 被系统性地教成对这类错误说「没错」。我们用 35B 思考模式逐句复核 9,505 句（训练负例 2,613 + 闭环种子回答的可改句子 6,892），再让 critic 采样 4 次复核同一批，**只有两边都说没错的才留作负例**（35B 自己偏宽松，只判出约 13–17%）。对照 Claude 抽查的 100 句：Claude 判有幻觉的 28 句规则去掉了 26 句（93%），Claude 判没错的 72 句误删 5 句。训练负例 2,613 → 2,063（去掉 550，21%），清洗后 Claude 再抽 200 个负例，残余 9/200 = 4.5%。

只清洗、不加任何合成数据，从基座按同样超参重训：

| 模型 | ++ 严格 P / R / F1 | ++ 有效 P / R / F1 |
|---|---|---|
| 基线 9B v2 | 0.865 / 0.245 / 0.382 | 0.841 / 0.393 / 0.536 |
| G0 合成 | 0.893 / 0.291 / 0.439 | 0.873 / 0.467 / 0.609 |
| G_free 合成（此前最好） | 0.869 / 0.305 / 0.452 | 0.840 / 0.471 / 0.603 |
| DPO v2 合成 | 0.867 / 0.269 / 0.410 | 0.842 / 0.430 / 0.570 |
| **critic-clean（只清洗）** | 0.827 / 0.434 / 0.569 | 0.778 / **0.619** / 0.690 |
| critic-clean-gfree（清洗 + G_free 600 对） | 0.816 / **0.509** / 0.627 | 0.746 / **0.656** / 0.699 |
| critic-clean-gtarget（清洗 + 定向改法合成） | 0.771 / 0.514 / 0.616 | 0.693 / 0.672 / 0.682 |

- 清洗对基线和 G_free 都显著（McNemar 有效正例 74 vs 1、59 vs 11，p < 1e-4）。提升集中在真幻觉上（real 召回 0.26 / 0.34 / 0.50），不是靠多报吹毛求疵换来的。原标注下精确率从约 0.5 降到 0.365，这是预期内的：多报的大多正是原标注漏标的幻觉。
- 在清洗基础上加 G_free，有效召回 +0.037（p = 0.10，不显著），严格召回 +0.075（显著），新增命中多在口径边缘的句子上。合成数据在干净数据上的边际作用变小了。
- 定向改法（张冠李戴、跨段拼接、数字细改等，类别来自对 ++ 错误的分析）没有可测增益，误报多 24 句。同批 Claude 抽查发现，35B 判有效、critic 4 次全没识破的 43 条里 27 条（63%）其实没错：critic 是对的，错的是有效性判断。

这一节也解释了 §5.4 里 DPO 为什么收敛到「句尾挂目的短语」：critic 被训成对这种模式视而不见，生成器自然就往那里跑。

代码：`ragtruth/negcheck.py`、`scripts/remote/run_negcheck.sh`、`run_cleancritic.sh`、`run_cleangfree.sh`、`run_closedtarget.sh`。

### 4.4 各种生成器的产出加进 critic

有了单字母 RM1（基线：清洗后人工数据 + 600 条 G_free 合成，++ 有效 AUC 0.9447、固定精确率 0.849 下召回 0.674），我们系统地比较了 DPO、GRPO 生成器（§5.4–§5.6）的产出能否提升它。判定标准事先定好：有效口径 AUC 和固定精确率下召回，配对 bootstrap 95% 区间不含 0 才算提升。

| 轮次 | 组 | ++ 有效 AUC |
|---|---|---|
| 第一轮：追加约 552 条 | dpo_all / dpo_hard / v2_all / v2_hard / v3_all / v3_hard | 0.9438 / 0.9301* / 0.9327* / 0.9351* / 0.9438 / 0.9269* |
| | human（去掉 600 条合成，只留人工） | 0.9424 |
| 第二轮 | repl_v3（用 v3 替换现有合成，正例比例完全相同）/ conf_all / conf_hard（只加矛盾类） | 0.9289* / 0.9337* / 0.9395 |

（* 显著低于基线）**没有一组超过基线。** 第一轮里阈值 0.5 的召回有涨，但判出同样多条时基线更高或持平，加样本只是改变了正例先验。第二轮的 repl_v3 正例比例和基线完全相同，排除了「先验变化」的解释，替换后反而变差；只加矛盾类也没补上矛盾类短板（矛盾类 AUC 基线 0.9232，各组 0.90–0.92）。

**种子少时是另一回事。** 只用 203 条人工种子时（基线 h200_2ep 有效 AUC 0.9102），加 912 行合成：G_free +0.0108、v3 +0.0001、DPO −0.0116；只有 G_free 在判出同样多条时召回显著（有效 +4.1 个点）。按金标重算后 G_free 在矛盾类明显错误上 +11.2 [+5.8, +16.2]。但在 914 行金标种子上加 G_free，明显错误反而 −0.0091 [−0.0163, −0.0006]。

**按金标重算全部组**（按原文抽样）：RM1 全部错误 AUC 0.9055、明显错误 0.9665；第一、二轮 10 组都没有显著高于 RM1。RM1 + 金标种子（rm1_gold）全部错误 AUC 0.9167（+0.0112 [+0.0029, +0.0200]），只用金标种子 914 行的 gold 0.9012（与 RM1 无显著差）。

**分歧挖掘的事后检验。** 不训练，只看能否找到 RM1 判错的句子：在金标评测集上各取前 20%，RM1 判错的比例随机 17.4%、RM1 自身不确定度 45.1%、11 个已有模型的委员会分歧约 32–33%。这只说明能找到判错样本，没有测加入训练后的效果。

当时的结论是「人工数据够多后，经 RM 奖励训练的生成器产出没有提升 critic」，于是停掉了这条生成器线。后来在核心集阶段（§4.9）才弄清楚：问题不在合成本身，而在加进去的样本大多是 critic 本来就会判的。

代码：`ragtruth/critic_aug.py`、`scripts/remote/run_rmarms.sh`；结果 `outputs/rt/realgen/critic_aug/compare*.json`、`outputs/rt/gold/gold_cmp*.log`。

### 4.5 目标模型自己的回答 + Claude 标注

在准备回答 GRPO 时，我们先摸底了 9B 原始模型的幻觉（§7.1），顺带发现现有 critic 在 9B 自己的回答上明显错误 AUC 只有 0.8757，没过事先定的 0.90 门槛。于是让 9B 在训练池 300 个原文上各写 1 条回答，Claude 标注 1,568 句（错误 627、明显 226），并入训练：

| critic | 9B 留出集 明显错误 AUC | 9B 留出集 全部错误 AUC | 金标评测集 全部 / 明显错误 AUC |
|---|---|---|---|
| RM1 | 0.8757 | 0.8215 | 0.9055 / 0.9665 |
| rm1_9b（RM1 + 9B 回答） | 0.8978（+0.0221 [−0.0110, +0.0558]） | 0.8615（+0.0400 [+0.0143, +0.0694]） | 0.9208* / 0.9739* |
| rm1_gold_9b（RM1 + 金标 + 9B 回答） | 0.9020（+0.0263 [−0.0049, +0.0584]） | 0.8609（+0.0394 [+0.0111, +0.0669]） | 0.9247* / 0.9742* |

（* 对 RM1 显著）这是合成数据各轮之外，第一次在金标和留出集上同时显著提升排序。代价是误报变多（非错误句 3/280 → 29–30/280）。rm1_gold_9b 之后成为 9B 金标 critic，只用于评测；同一份数据换 2B 底座得到 `rm1__mcgold`，作为全 2B 阶段的基线 critic。

代码：`ragtruth/base_eval.py`、`critic_aug build6`。

### 4.6 2B critic 的边界样本、清洗与拒答标签

全 2B 阶段，错误生成器 a7（§5.8）造了 42,664 条，合格 6,960 条。我们按 2B critic 分数取边界段 0.1–0.7 的 1,500 条错句 + 配对原句加进 `rm1__mcgold`，并设同条数不限区间的对照：

| critic | ++ AUC | recall@0.5 | precision@0.5 | 验收回答 clear AUC | 边界段内 AUC |
|---|---|---|---|---|---|
| rm1__mcgold（基线） | 0.859 | 0.566 | 0.757 | 0.748 | 0.605 |
| h1（边界 1,500） | 0.848 | 0.618 | 0.700 | 0.752 | 0.540 |
| h1ctl（不限区间 1,500） | 0.862 | 0.644 | 0.727 | 0.765 | 0.612 |
| h2（清洗后 847） | 0.861 | 0.655 | 0.717 | 0.764 | 0.605 |
| h2n（不清洗 847） | 0.856 | 0.619 | 0.740 | 0.721 | 0.562 |

（验收回答 = 200 条 2B GRPO 回答，800 句，错 193、clear 75。）边界区整体被抬高，区分能力没变：新增判出的真错 18 条，新增误报 22 / 18 条。h1 的 1,500 条里 Claude 抽 90 条只有 77% 是真错，23% 是忠实改写、合理概括或省略，约 350 条错标正好解释了误报上升。清洗后的 h2 把区分度补回到基线水平，但没有超过；随机取合格样本的 h1ctl 一样好。**标签噪声是 h1 变差的原因，但不是边界区分不开的主要原因。**

**拒答标签。** 2B 回答里有一类明显错：原文能回答，却说「Unable to answer based on given passages.」。基线 critic 对拒答判错 0%（P 恒为 0.012），9B 金标 critic 也只有 5%：两者都被训练标签教成「拒答不算错」（训练集 30 句拒答有 25 句标为有依据，其中 9B 回答的 16 句里 10 句原文能回答）。修正版 `rm1__mcgold_ref` 把能回答的拒答改标为错，并补拒答样本：拒答评测判错 yes 97% / partial 83%，验收回答 clear AUC 0.748 → 0.795，++ AUC 基本不变（0.855）。代价后来才看到（§4.7）：普通显然错误的召回有所下降。

代码：`ragtruth/critic_harvest.py`、`ragtruth/critic_refuse.py`、`scripts/remote/run_harvest.sh`、`run_clean.sh`、`run_refuse.sh`。

### 4.8 纯人工 vs 纯合成

| hum | 0.804 [0.771, 0.836] | −0.018 [−0.044, +0.009] | 0.51 | 0.848 / 0.384 / 0.830 |

### 4.9 核心集上：sev 筛过的真错 vs critic 拿不准的真错

核心集阶段的 critic 底座是 `rm1__core`（4,604 行）。第一次循环用 sev 门槛造的 550 对补成 r1（不限 critic 区间）；随后从同一批采集里只取 critic 拿不准（P < 0.3 的盲区和 0.3–0.7 的边界）、且经 Claude 核实为真错的 581 条错句 + 原句，得到 r2。

同时我们用 9B 错误改写模型（§5.10）的样本做了另一组对照：

| critic | 加了什么 | 显然错 AUC | 对底座 | 误报 10% 召回 | ++ AUC |
|---|---|---|---|---|---|
| rm1__core | — | 0.843 | — | 0.58 | 0.831 |
| sevs1 | 旧 sev 按分取 733 | 0.843 | −0.001 [−0.017, +0.014] | 0.59 | 0.826 |
| sevrnd | 不过滤随机 733 | 0.842 | −0.001 [−0.015, +0.011] | 0.56 | 0.822 |

### 4.10 长句增强（r3）

用 r2 当奖励接着训 RAG（§7.7）时，策略开始合并句子：Summary 里 ≥ 35 词的长句从 7.5% 升到 11.1%，QA 里含分号列表式长句的回答从 19 条升到 49 条（共 293 条），新增的显然错大多来自长句。r2 的召回随句长下降：15–25 词 0.49、25–35 词 0.27、≥ 35 词 0.14。

为了堵这个洞，我们把种子集 1,000 个 Claude 核实的错误对与相邻 1–2 句拼成长句（错误版、改对版各 1,000 行，中位 47 词）加进 r2，得到 r3。++ AUC 0.837 → 0.846，长句（9B 显然错 14 句）误报 5% 召回 0.36 → 0.50；但 Claude 金标显然错 AUC 0.872 → 0.850（−0.022 [−0.039, −0.008]，显著变差）。拼接长句不够自然，critic 可能学到了拼接痕迹。长句增强的作用是**防守**：堵住「合并句子躲 critic」，让接着训不再退化，但没有让 critic 更会抓错。

代码：`ragtruth/merge_aug.py`。

## 5. 错误生成器

错误生成器的任务是造出 critic 学得到东西的错误样本。它经历了很多版，大部分以失败告终，但每次失败都指出了一个具体问题。按时间顺序，前半部分（§5.1–§5.6）在 9B 上做，后半部分在 2B 上。

### 5.1 指定改法合成与「判有效」的难题

最早的 G0 是 35B / 9B 按 13 种改法之一改写（§4.1）。合成样本的有效性一直是个难题：35B 判有效的样本里有相当一部分其实没错，而且越是 critic 识破不了的越可能没错。我们花了不少力气把「判有效」做准，最终形成了 RM3 的训练数据：

- 35B 思考模式直接判：和 Claude 四分类一致 63%、两档 72%，19% 思考到上限也没给结论；偏宽松，Claude 判「其实没错」的 40 条里 35B 判正确 15 条。
- 把边界写清楚、改成严格口径后（v3），35B 和 Claude 四分类 77%、两档 83%。35B 判「不正确」很可靠，判「正确」的约 3 成有问题。
- 同一模型同一提示词复判一次，两次判定高度相关，筛不掉错样本。改成怀疑式四步审查（v5：先查原句、再判改动是否算错、自己定类型再比对、最后查证据和理由）后，判合格的精度明显提高（在用来改提示词的样本上 97%，新抽样 88%），代价是召回下降。
- 冲突和拿不准的样本交 Claude，合成最终 RM3 训练集 4,635 条（正 1,760 / 负 2,875）和 358 条全 Claude 标签的评测集。9B 单字母 RM3：评测集 AUC 0.894、ECE 0.119，阈值 0.5 时 P(合格) 精确率 0.912、召回 0.758。

RM3 后来在 2B 生成器的边界样本上失效（§5.8），被 sev 取代。

代码：`ragtruth/audit_synth.py`、`ragtruth/rm3_merge.py`。

### 5.2 真实性判别器与生成器—判别器—critic 循环

思路类似 GAN：文本无法把梯度回传给生成器，用 DPO 传偏好。判别器 D 区分「RAGTruth 人工标出的自然错误」和「合成错误」，输入只给原文、目标句和前后各一句，防止它利用「回答别处有没有错」的捷径。D1 留出 AUC 0.926、准确率 0.897：合成错误和模型自然犯的错很容易区分。按改法看，「调换主客体」「加原因或动机」对 critic 很难，但最不像真实错误，是典型的「为错而错」；「加结论或概括」「加看似合理的常识」既难又相对像真。

两轮循环（G 采样 → 35B 判有效 → critic 打难度 → D 打真实性 → 帕累托占优组偏好对 → DPO）：G1 的 DPO train_loss 0.692、偏好准确率约 0.58，几乎没学到东西；C1 召回 0.840、C2 0.835，第 2 轮没有额外提升，因为 G1 产出在 C1 下难样本只有 4.4%。DPO 学不动有两个原因：生成器只会 13 种改法，起点不在真实分布上；学习率 5e-6 是全参数微调的量级，对 LoRA 偏低。

### 5.3 用真实错误 SFT：G_sft 与 G_free

为了让生成器从真实分布出发，我们让 35B 把 RAGTruth 里的真实错句「修好」，再训生成器把修好的回答还原成真实错句。修复质量经 Claude 抽查迭代到 80% 合格后放行。再进一步，把句子、类型、改法都交给生成器自己选（自由版 G_free）：

| | G0 指定版 | G_sft 指定版 | G0 自由版 prompt | G_free |
|---|---|---|---|---|
| 有效率 | 30.6% | 24.9% | 23.8% | 29.2% |
| D1 判为自然 | 8.9% | 19.1% | 18.7% | 39.7% |
| 有效样本中的难样本 | 5.3% | 10.4% | 7.7% | 12.0% |
| 改法分布与真实的距离（TV） | 0.269 | 0.349 | — | 0.122 |

只换自由版 prompt 自然度就翻倍，再加真实错误 SFT 又翻一倍。G_free 此后成为参照，它的 600 对合成也进入了 RM1 的训练集。

代码：`ragtruth/realgen.py`、`scripts/remote/run_realgen_free.sh`。

### 5.4 生成器 DPO：循环内指标变好，金标上反而变差

DPO v1 有 80% 的偏好对是「有效 > 无效」，学成了「写有效的错」：有效率 29% → 50%，但自然度和难度都降了。v2 把有效、难、真加权成一个分数再配对（chosen 必须有效，且难、真百分位都 ≥ 0.5），三个目标同向改善：难样本 12% → 21%，自然度 40% → 47%，每 1,200 条采样里「有效且难」的从 42 条翻到 84 条。

但闭环验证给出了相反的答案：同一批回答、同样选 600 条，DPO v2 组的 critic 在 ++ 上召回 0.269，显著低于 G_free 组的 0.305（McNemar p = 0.006）。Claude 盲审各 50 条，两组都是 94% 真错，推翻了「改得太轻不算错」的猜测。真正的区别是 DPO v2 的 baseless 大量是在句尾挂一个目的或方式短语（"…for tenderness"、"…to ensure even browning"），改法字段也退化成自由描述。奖励是「C2 抓不到 + D 判自然」，挂个短尾巴最省力，于是收敛到这个窄套路，critic 学到的 baseless 也跟着变窄。在 DPO v2 的样本池里再挑「难 + 真」也补不回来（0.266，与随机挑持平）。

另一个更大的问题在这时浮出来：四组 critic 在 ++ 上 conflict 召回都只有约 0.2，而 ++ 新增的 542 句漏标几乎没动（召回 0.18–0.22）。生成器怎么换，都只在「原标注能标出来的那类错」上做文章。这直接引出了 §4.3 的负例清洗。

代码：`ragtruth/gen_dpo.py`、`scripts/remote/run_freedpo2.sh`、`run_closeddpo2.sh`。

### 5.5 Claude 修复的种子生成器与 RM 打分 DPO

既然生成器只需要「种子级启动」，后面靠 RM 打分反馈，我们改为追求多样性和覆盖面：真实错句按（任务、类型、明显 / 隐蔽、位置、改动大小）分成 135 格，每格最多 12 句、6 个模型轮流，由 Claude 重新修复，最终修好 1,101 句、覆盖全部 135 格。

种子生成器 G_seed 本身不如 G_free（RM3 合格 19.4% vs 27.3%），主要因为它学会了大改，而评测规则沿用了合成时的改动上限。放开规则、只看多样性后，用 RM1 难度、RM2 真实性（交叉折打分，避免见过的样本）、类型 × 改法稀有度加权做 DPO：

| | 合格率 | 不同合格错误 @16 | 改法熵 | 难样本（RM1 < 0.5） | 合格样本 baseless / conflict |
|---|---|---|---|---|---|
| G_seed | 32.7% | 4.66 | 2.41 | 9.9% | 554 / 481 |
| G_dpo（第一轮） | 50.1% | 6.10 | 1.58 | 18.7% | 1,563 / 24 |
| G_dpo2（按类型分组、同类型配对） | 63.8% | 7.99 | 1.98 | 13.4% | 1,296 / 725 |

第一轮 DPO 出现类型塌缩：conflict 几乎消失，改法集中到「看似合理的真实世界事实」「原文没有的评价」「结论 / 概括」，正是 RM1 难识破、RM2 觉得像真的那几类，0.5 权重的多样性加分拦不住。第二轮把难度和真实性按类型分组算百分位、chosen 和 rejected 必须同类型，解决了塌缩，合格率和多样性都是最好的，代价是难度和真实性的提升变小。

代码：`ragtruth/gen_seed.py`、`ragtruth/gen_dpo_rm.py`、`ragtruth/gen_eval.py`。

### 5.6 9B 生成器 GRPO 与改法名 reward hack

从 G_dpo2 出发做 GRPO，奖励 = RM3 门槛 + (难度 + 真实性 + 多样性) / 3，硬规则拦住解析失败、照抄、点破题目的词等。训练中出现了一个典型的 reward hack：多样性分按「类型 × 改法」计数，而改法是模型自填的字符串，对不上标准名时保留原文，新名字计数为 0、拿满分。第 100 步时改法名从 18 种涨到 71 种（"a preheating step"、"a closing time that the source never mentions"…），而不看改法的真实多样性基本没涨。修法是把改法封闭到 13 种标准名 + other，多样性改成按最近 512 条合格样本的窗口计数。

我们还加了独立裁判：每隔一段步数抽 100 条 RM 判合格的样本给 Claude 盲审（看不到模型理由、RM 分数和检查点来源）：

| | 起点 | full_v2 第 100 步 | 第 200 步 | 第 300 步 | full_v3 第 300 步 |
|---|---|---|---|---|---|
| Claude 认可率 | 92.9% | 80.6% | 89.4% | 82.5% | 83.5% |
| 全部产出里 Claude 也认可 | 58% | 57% | 70% | 65% | 68.8% |
| 又难又被认可 | 7.9% | 13.9% | 12.5% | 14.1% | 12.0% |

认可率起点 91–93%，和 RM3 在 Claude 评测集上的精度吻合；训练后降到 80–83%，但总的认可产出略有增加。Claude 的「真实」判断从 93% 降到 82%，而 RM2 的自然度在涨，方向相反；拆开看不是靠句子变短骗 RM2，下降集中在矛盾类和 RM2 低分段。full_v3 把多样性改成「同一 prompt 里换位置」，不看改法的多样性 +23%，代价是难度下降。

这些生成器的产出加进 critic 的结果见 §4.4：都没有超过基线。

代码：`train/gen_grpo.py`、`train/gen_reward.py`、`ragtruth/gen_audit.py`；奖励设计见 [rewards.md](rewards.md) 的「第一代生成器的奖励」。

### 5.7 三个单字母判别器

全 2B 之前，三个判别器统一成单字母格式（9B）：RM1（§3.5）、RM2（自然 / 合成，留出 AUC 0.958）、RM3（四分类，§5.1）。RM2 后来多次重训（合成一侧换成当时生成器的产出），测试 AUC 一直在 0.96 左右：G_seed 造的合格错误和真实错误仍然很好区分。

**RM2 为什么这么好分。** 表面特征（长度、照抄原文、位置、任务、数字、词袋）AUC 只有 0.60–0.61。一部分信号是「错得明显」：合成一侧都过了正确性门槛，几乎全是明显错（2B 任意句 P(自然) 0.93、2B 真错轻微 0.86、明显 0.67、合成 0.09）；另一部分是生成器自己的写法：动数字 22.5% vs 8.5%、几乎换整句 20% vs 10%，还有拼接留下的语病。RM2 分数很尖（合成样本中位数约 0.004），我们用对数几率映射拉开数值，没有另外训软。要注意：每换一版生成器，RM2 的合成负例都要跟着换，否则新生成器分数高可能只是「不像旧生成器」。

### 5.8 2B 定向生成器与奖励形状 a0–a12

全 2B 阶段的生成器目标是造 2B critic 漏掉的那几类错（§9.1）。前三版 GRPO（种子分别来自 RAGTruth 别的模型的错句、2B 自己的错句、按上下文重新改对的 2B 错句）出现了同一个规律：

| 版本 | 留出集骗过 2B critic（起点 → 结束） | RM2 判自然（起点 → 结束） | 停训原因 |
|---|---|---|---|
| 第一版 | 3.3% → 2.0% | 13.1% → 4.6% | 张冠李戴一类占 0.601 |
| 第二版 | 15% → 8.2% | 5% → 7.4% | conflict 占 0.952 |
| 第三版 | 19.2% → 6.2% | 15.4% → 8.7% | 改法名数翻倍 |

合格率和多样性上去了，骗过 critic 和真实性却往下掉。种子越好起点越高，但 GRPO 把它推回去。门槛检验显示，合格样本内部也随训练往下掉：奖励本身在把生成器往「明显的错」推。

接下来围绕奖励形状做了一系列对比（起点是 151 条只取 critic 判不出的种子）。两条关键观察：critic P(判出) 极低的样本 Claude 只确认 11/33 是真错（多是正确性门槛误判）；P ≥ 0.98 的几乎都是明显错。所以奖励应偏向 critic 边界。各版用每 prompt 16 次的放大评测比较：

| 版本 | 奖励要点 | 合格 | P ≥ 0.9 的明显错 | 0.1–0.7 估计真错 |
|---|---|---|---|---|
| 起点 | — | 439 | — | 87 |
| a6 | 系数 max(0.05, 4P(1−P)) | 949 | — | — |
| a7 | 没过门槛给固定 0.1；合格 = 自然度 × 4P(1−P)；P ≥ 0.98 记 0 | 394 | 170 | 约 101 |
| a8 | 帐篷形系数（峰值 0.3） | 316 / 263 | 113 / 102 | 93 / 69 |
| a9 | 保底分级 0.1 × P(真错) / 0.7 | 673 / 662 | 426 / 431 | 102 / 104 |
| a10 | a7 系数 + a9 保底 | 712 | 468 | 104 |
| a11 | 4P(1−P) 只在 [0.1, 0.9) | 670 | 447 | 98 |
| a12 | 明显的错 −0.1 | 547 / 463 | 318 / 263 | 106 / 84 |

（两个数的是第 50 / 100 步。）a6 涨的几乎全是明显错：没过门槛记 0，明显的错仍高于 0，照样拿正优势。a8 把明显错全记 0 后，固定 0.1 的保底让「不造错」成了退路。各版目标段真错都在 98–106，差别在纯度：a7 固定保底让明显错比不造错还亏，目标段占合格 32%，明显错最少，于是选 a7 第 50 步造数据（harvest h1，§4.6）。

**RM3 在边界样本上失效。** 504 条 Claude 判过的合成错句（已过门槛 0.7）上，RM3 P(A+B) 对真错 / 不是错的 AUC 只有 0.51，RM2 0.42，2B critic 0.57；门槛从 0.7 调到 0.9 纯度只从 79% 到 81%。加入这 504 条重训的 RM3 v2 也只到 0.634。后来定位到一个格式问题：RM3 训练和造数据打分时给的是改写前的原回答，而 v2 和 sev 用的是已替换成改写句的回答，所以「重打平均只有 0.47」是格式错位，同格式应以 0.549 为准。

**sev__mc。** 于是改训严重程度判别器：Claude 对生成器样本标 6 选 1（显然 / 轻微 × 解释对 / 错、没有错、原句有错），三批 787 条，显然错里解释对的只有 35%，所以门槛只看「句子是否真错」。sev__mc 的 P(显然) AUC 0.805（同样本旧 RM3 0.551），在 critic < 0.5 的盲区独立测试（239 条）上 0.714（旧 RM3 0.517），门槛 0.5 时入库样本「有错」的比例 93%。半量数据训的版本 AUC 只差 0.01，学习曲线已经很平。

代码：`ragtruth/gen_target_data.py`、`ragtruth/gen_seed2b.py`、`train/gen_reward.py`（TargetRewarder）、`ragtruth/sev_label.py`、`ragtruth/sev_rm.py`、`scripts/remote/run_rewardexp*.sh`。

### 5.9 sev 门槛的生成器（全 2B 末期）

奖励改为 sev P(显然) ≥ 0.5 门槛、合格时 (1 − P(critic)) × 自然度。前 50 步合格率 17.4% → 25.5%，但每条样本的「盲区显然错」产量一直是 1.39%：大多数合格样本 critic P ≈ 0.9、自然度 ≈ 0.15，组内拉不开，梯度主要来自保底项。续训 50 步改成只给 critic 0.3–0.7 加分：放大评测边界样本每条 1.35% → 2.43%，全部来自合格率上升，合格里边界占比不变（7–8%），critic 一眼看出的涨得更多。用第 100 步造的 13,071 条合格样本就是 §4.7 那批对照的数据来源。

代码：`scripts/remote/run_gensev.sh`、`run_h3.sh`。

### 5.10 核心集阶段：SFT 生成器审计、9B 生成器、sev 当过滤器

**SFT 生成器本身。** gen-core-mc（种子集 SFT）的原始输出 751 条 Claude 标注：显然错 29% / 细微错 41% / 没错 30%，严格口径真错约 70%。解释三项分开判（517 条真错）：类型对 60%、证据对 62%、理由对 51%，三项全对只有 27%。生成器常把 baseless 说成 conflict（声明 conflict 的 249 条里 141 条实际是 baseless），理由常和证据一起错（指向了别的改动）。种子集本身三项全对 92%，所以这是模型没学会，不是训练数据错。

**换 9B 生成器。** 同种子集、同提示配对审计：

| 组 | 显然错 | 没错 | 真错里三项全对 | 真错且全对 / 全部 |
|---|---|---|---|---|
| 种子集 D3 | 41% | 4% | 92% | 88% |
| 2B | 33% | 35% | 23% | 15% |
| 9B | 30% | 38% | 38% | 24% |

9B 的解释明显更好（真错且全对 +7.5 [+2.1, +12.8]），但造出真错的比例没变，两者都有三分之一以上其实没造出错。瓶颈不在模型大小。

**sev 当过滤器。** sev__core 给 9B 样本打分，「是不是真错」AUC 0.784，≥ 0.9 留 46%、精确 84%；判「解释对不对」只到 50–75% 且只留极少。我们又改用生成器真实输出 + Claude 统一审计训 sev__gen：判真错 AUC 0.796 → 0.837（+0.041 [+0.014, +0.071]），判解释没有提升。sev__gen ≥ 0.8 仍有 11% 其实没错，人工看这些样本，共同点是生成器写了像样但不成立的理由，sev 跟着理由走。于是试了两个输入变体：加逐词改动标记（diff）没有帮助；去掉生成器的类型、证据、理由（dne），判真错更好（+0.019 [−0.005, +0.044]，9B 样本 +0.032 [−0.005, +0.068]），混入没错的更少。

**奖励「骗过 critic」的生成器。** 核心集阶段的第一次尝试是直接奖励盲区：gated 版以 sev 真错和 critic 盲区为硬门、自然度为唯一优化目标；add 版把 critic 盲区（主）和自然度（次）相加。gated 生成器采出 4,376 条真错池、挑出 987 条盲区错，补进 rm1__core 后（不配原句 / 配原句两种），同误报率口径下整体召回 0.555 → 0.522 / 0.516，Claude 金标 AUC 0.830 → 0.810，都变差。只看固定 recall@0.5 会误以为「救回了 45% 的盲区」。Claude 独立审 200 条：错句里只有 48 条（24%）是真错，配对原句 92% 正确（说明不是 Claude 太严）；真错率随盲区深度单调下降（critic P < 0.1 只有 14%，0.3–0.5 为 38%）；把生成器的类型、证据、理由喂给 Claude 复核 152 条「没错」，只翻了 2 条。奖励等于「骗过 critic + 过一个和 critic 同源、边界上同样弱的 sev」，GRPO 就坍缩成造 sev 会误判的非错句。对照前面的审计，SFT 生成器本身约 70% 是真错，低产出来自 GRPO 加盲区筛选。

**sev 在 critic 盲区里不可靠。** 按 critic 分数分段看 dne ≥ 0.8 的效果：critic ≥ 0.5 区域留 80%、真错率 93%；critic 0.1–0.5 区域（真错率 36%）sev 排序 AUC 只有 0.67–0.71。sev 和 critic 同是 2B，一起失明，sev 的高精度只在 critic 本来就判得出的区域，在盲区里只能当预排序。

代码：`ragtruth/expl_label.py`、`ragtruth/gen_audit.py`、`ragtruth/sev_gen.py`、`ragtruth/sev_filter_score.py`、`scripts/remote/run_gen9b.sh`、`run_sevgen.sh`、`run_sevvar.sh`。

### 5.11 生成器 v2：按机制出题

旧生成器声称的改法和 Claude 判的实际机制一致率只有 2–27%。v2 改成：输入原文 + 完整回答 + 9 个细类机制之一（名字和 Claude 标注、sev 共用），输出改哪句、改写句和一句自然语言的改动描述；不再输出类型、证据、理由，提示词里也去掉「尽量少改」。训练数据是种子集真实错误对，改动描述由 9B 基座写意思层面的描述，Claude 抽查后补写了 934 条。

输出顺序试了三种（9B，Claude 评测）：先 edit 后句子 真错 72–74% / 机制一致 28–29% / 自然 78–85%；先句子后 edit 73% / 33% / 96%；只出句子 62% / 26% / 84%。定版为「先句子后 edit」，edit 只当训练辅助信号。生成器自己写的 edit 准确率只有约 4 成（它看不到逐词差异），所以推理时改动清单用规则 diff，给 sev 另加 9B 基座事后写的描述。

**sev v3 系列**：输入带要求的机制 + 9B 描述 + 规则改动清单，4 选 1（要求的那种·显然 / 要求的那种·细微 / 别的错 / 没错）。只给规则清单判「有没有错」0.848，加 9B 描述 0.908。用新生成器的 1,444 条 Claude 标注扩充后（v3b），判「要求的那种」0.726 → 0.784，张冠李戴提升最大（0.53 → 0.81），范围偏移仍弱（0.49），矛盾没动。

分析标注后发现**直接矛盾是「结果」不是「手法」**：Claude 判为矛盾的 252 条里 197 条原本要求的是别的类型；要求矛盾的 366 条只有 15% 判为矛盾，但 64% 是真错。所以 v3c 把矛盾放宽为「真错即可」，并补了 294 条范围偏移标注；只补不放宽的版本叫 v3c0。放宽后 v3c 在新口径上 0.829、同阈值留得更多。后续生成器实验用 v3c0 打「有错」和「要求类型」。RM2 用 Claude 的「自然」标签重训（rm2__v3 0.846，扩充后 v3b 0.901）。

代码：`ragtruth/gen_v2.py`、`ragtruth/gen_v2_label.py`、`ragtruth/sev_gen.py`、`ragtruth/rm2_v3.py`、`scripts/remote/run_v3c.sh`。

### 5.12 v2 的 GRPO 与难样本迭代

**sev 当主奖励。** ga：门槛 RM2 ≥ 0.5，奖励 sev P(要求的那种)；gb：再加 critic ∈ [0.1, 0.7) 门槛。在留出原文 2,520 条上：

| | v0（SFT） | ga | gb |
|---|---|---|---|
| sev ≥ 0.5 | 9.0% | 35.1% | 14.4% |
| + 自然 + critic 0.1–0.7 | 1.5% | 2.8% | 3.4% |
| critic P 中位 | 0.72 | 0.91 | 0.70 |
| Claude 抽查：真错 + 类型一致 + 自然 | 52% | 67% | 52% |
| 折算真合格产出 | 4.0% | 20.2% | 6.5% |

sev 奖励真实有效，真合格产出约 ×5，但多数是 critic 已能判出的错，落在拿不准区间的增量很小。critic 门槛进训练（gb）几乎没有正样本，学不起来。

**critic 难度当主奖励。** 门槛 sev P(有错) ≥ 0.9 + 自然 ≥ 0.5，然后按 critic 分数给难度分。h1：三角形（0.3–0.5 为 1）+ 过门槛保底 0.1；h4：三角无保底；h2：只奖励 < 0.7。保底让明显错比没过门槛更划算，h1 反向跑（≥ 0.9 占比 55% → 72%）；去掉保底后方向对了，但 50 步在留出提示上几乎没动。根源是信号太稀：过门槛样本里只有约 5% 落在 0.1–0.5，大多数组内的样本都在 0.7 以上，奖励几乎相同。组内排名奖励强化的是「过门槛」而不是「更难」，也放弃了。

**难样本 SFT 迭代。** 改为「采样 → 挑难样本 → SFT」：在训练提示上大量采样，挑过门槛、critic 0.1–0.7（后来收紧到 0.1–0.5 且 sev 判要求类型 ≥ 0.5）的样本，和原 SFT 数据一起再训。迭代过程中我们发现提示的多样性比采样次数重要：与其对同一提示采 12 次，不如让 RAG 模型对每个原文高温采 8 个不同回答，挑 critic P < 0.1 的干净句，每个（回答，类型）只用温度 0 采 1 条。这样难样本率从 0.54% 翻到 1.16%。

| 生成器 | 过门槛 | 其中 critic < 0.5 | 其中 ≥ 0.9 | 过门槛且 critic 0.1–0.5（/ 2048） | 没有 0.1–0.5 样本的组 |
|---|---|---|---|---|---|
| SFT 起点 | 28.0% | 5.6% | 55.5% | 29 | 42 / 64 |
| v2h（第一轮难样本 SFT） | 32.4% | 6.0% | 50.5% | 36 | 41 / 64 |
| v2h2 | 27.9% | 7.3% | 48.6% | 37 | 42 / 64 |
| g1（v2h2 + GRPO 50 步） | 31.9% | 7.2% | 45.3% | 42 | 38 / 64 |
| v2h3（大提示池难样本 SFT） | 25.6% | 8.8% | 43.0% | 39 | 40 / 64 |

过门槛样本的 critic 分布一路往下移，但真正能用的难样本一直卡在约 40 条。生成器每轮能造出五六百条 critic 拿不准、读着也自然的句子，大部分倒在了 sev ≥ 0.9 这道门槛上（tech_share_details 表 5）。

**放宽门槛后的 Claude 抽查。** 5 个版本试采样本里 critic 0.1–0.5、自然、sev ≥ 0.5 的 821 条，每种要求类型抽 10 条，共 88 条：真错 66%（显然 16%）、自然 91%、类型一致 31%。sev 仍有排序作用（0.5–0.8 真错 61%、0.8–0.9 75%、≥ 0.9 79%），门槛从 0.9 放到 0.5 候选约 ×6、真错约 ×5。真错的实际机制集中在范围偏移、张冠李戴、近义偏移，正是 critic 漏判最多的几类。**生成器能造出 critic 盲区的真错，之前是用一个和 critic 一样瞎的模型去验，把它们都挡掉了。** 类型控制弱没关系，入库时用 Claude 判定的实际机制做标签即可。

各类型的造难能力不同：范围偏移难样本最多、类型保持最好；添加事实、直接矛盾、无依据推断一旦造得难，就不再是原类型；数字日期难样本最少，但多为真错。

代码：`train/gen_reward_v2.py`、`ragtruth/gen_v2_grpo.py`、`ragtruth/gen_pool_rag.py`、`scripts/remote/run_gengrpo.sh`、`run_gengrpo_cmp.sh`、`run_gen_b.sh` → `run_gen_c.sh` → `run_gen_d.sh`、`scripts/gate_stats.py`。

## 6. 盲区补样本

有了「critic 拿不准 + 真错」才有用的认识（§4.9），这一章是把它做成可重复的流程：选类型 → 造候选 → 按 critic 分数和 sev 取样 → Claude 核实 → 补进 critic → 按类型复查。critic 底座是 r2。

### 6.1 只补一个类型：范围偏移

范围偏移是 critic 最大的盲区（漏判里占 35%，该类漏判率 76%），也是生成器造难能力最好的类型。9B 生成器 v2 按范围偏移采样 10,526 条，经 sev、RM2、critic 区间筛选得 609 条，Claude 核实后真错 + 一致 + 自然 285 条。

| critic | 显然错 AUC 差 | 任意错 AUC 差 | 范围偏移（154 句）AUC 差 | 范围偏移召回@误报 10% |
|---|---|---|---|---|
| r2 | 0.872 | 0.808 | 0.731 | 0.31 |
| + 285 条，Claude 核实，配原句 | −0.014 | +0.002 | **+0.030 [+0.012, +0.050]** | 0.36 |
| + 285 条，不核实（约一半是真合格） | −0.012 | +0.002 | +0.007 [−0.012, +0.027] | 0.30 |

一开始只看显然错口径，两组都略差于 r2，以为白做了。后来发现 Claude 把大多数范围偏移标为「细微」（154 句里显然 20、细微 134），只看显然错根本看不见这个类型。改用任意错和按类型口径后：**定向补数据对目标类型有显著提升，而且只有核实组显著**。去掉配对原句对其他类型的伤害变小，但显然错主口径仍掉约 0.013，主要代价是只补单一类型本身。从这时起 critic 评测固定看三个口径：显然错、任意错、按类型。

## 7. RAG 强化

### 7.1 9B 回答 GRPO

**摸底。** 9B 原始模型在金标评测集原文上各生成 16 次，Claude 标 100 条：带任意错 76%，带明显错 46%（QA 15/60、Summary 31/40）。事先定的两个门槛：带明显错的回答 ≥ 30%（过），critic 明显错 AUC ≥ 0.90（RM1 只有 0.8757，没过）。于是先改进 critic（§4.5），用 rm1_gold_9b 当回报。

**奖励。** 1 − (0.5 × 平均 P(有幻觉) + 0.5 × 最大 P)，连续概率不用阈值；硬规则 0 分：空、截断、拒答、长度超出该 prompt 上原始 9B 中位长度的 0.5–1.5 倍、照抄原文。学习率在 5e-6 / 2e-5 / 5e-5 上各试 15 步，取 KL < 0.01 的最大值 5e-6。

**满意度护栏。** critic 只看忠实度，测不到答非所问、故意打断、抄袭、字数很少这类钻空子。我们训了一个只管结构和是否解决问题的满意度模型（相对版 pair 和绝对版 1–5 分，Claude 一次调用同时标），加上程序构造的四类反例各 100 条。sat_pair 留出准确率 83.5%、AUC 0.936，sat_abs 81.5%、0.917。接进 GRPO 的方式是只罚不奖：每个 prompt 固定一条原始回答当参考，奖励 − w × max(0, 0.5 − P)，避免模型去钻满意度模型本身的空子。

**Claude 验收**（同 100 个原文和种子，按原文配对 bootstrap）：

| | 9B 原始 | 第一轮第 150 步 | 第二轮第 200 步（加满意度护栏） |
|---|---|---|---|
| 带错误回答 | 76% | 59%（−17 [−25.5, −8.8]） | 64%（[−22.6, −1.1]） |
| 带明显错误回答 | 46% | 24%（−22 [−31.6, −12.9]） | 20%（[−37.6, −15.0]） |
| 句错误率 | 37.7% | 19.0% | 22.3% |
| QA / Summary 带明显错误 | 25% / 77.5% | 15% / 37.5% | 6.7% / 40% |
| 回答质量（Claude 盲评 50 对） | — | 4.26 → 4.24 | 4.20 → 4.28 |

第一轮 QA 有「少说」倾向（漏关键信息 11.8% → 20.6%），奖励鼓励少说的方向和它一致。第二轮改为从第 0 步开始（而不是从第一轮中途分支），因为变化最快的是前 100 步，分支的话那段走偏已经发生，护栏作用看不全。

**critic 在 GRPO 回答上还准不准。** critic 给第 150 步验收回答打分和 Claude 比：排序基本还在（明显错误 AUC 0.902 → 0.885），但 0.5 阈值的全部错误召回 0.622 → 0.321，确定性或范围改变 0.58 → 0.18。幸存者偏差和「学会绕开 critic」在这里还分不开。

代码：`train/ans_grpo.py`、`train/ans_reward.py`、`ragtruth/ans_data.py`、`ragtruth/ans_accept.py`、`ragtruth/sat_data.py`。

我们把进奖励的所有模型都换成 2B（9B 只在训练外打分），以便在一张卡上完成整个循环。MiniCPM5-2B 关闭思考时 QA 60 条拒答 53–54 条，加系统提示（有相关信息就回答，只有完全没有才拒答）后降到 14 条，采用关闭思考 + 系统提示。lr 5e-6，300 步。

| 200 | 27% | 47.5% | 19.3% |
| 300 | 26.5% | 45.5%（[−21.5, −8.5]） | 17.5% |

2B 降 23.5 个点、9B 只降 13 个点，一部分是迎合 2B critic，但 9B 下句子级幻觉也减半。拒答 9.5% → 1%。

### 7.3 换一个「更好」的 critic 当奖励（h2）

`rm1__mcgold_h2`（§4.6）当奖励，其余不变，300 步。9B 打分：两版都比起点大幅下降（含显然错回答 48.5% → 约 27–31%），但新旧之差在各步都在 ±5 个点内、不显著，验收集上 h2 版还略差（显然 18.5% vs 21.5%）。Claude 复核两版 9B 高分句各 25 句，结论一致。h2 当奖励没有带来超出基线 critic 的提升。

### 7.4 奖励粒度：句子层优势（表 1）

旧公式的问题：第 1 句错扣 0.6，之后每句只多扣 0.1；同样 1 句错，10 句的回答比 5 句的分数高（稀释）。直接改成「至少一句错的概率 + 期望错句数」会把底噪按句数累加：ref critic 给没错句子平均 P 0.10，显然错的中位数只有 0.20，结果 8 句全对的回答分数反而低于 4 句带 1 句显然错的。于是：

- R1 整段层：减去同组所有回答所有句子的平均 P（底噪），按超出部分计数，K = max(2, 0.5 × 参考回答句数)；满意度扣分最多 0.4。
- R2 句子层：在 R1 之外，把 −max(0, p − b) / σ 只加在出错那一句的 token 上，权重 β = 0.6；没超出底噪的句子为 0，不奖励多写。
- R3：后一句的负值再按 γ = 0.3 传给前一句。

四组同一 critic（h3ctl）、同起点、各 50 步，200 条配对回答 9B 打分（tech_share_details 表 1）：

| 奖励 | 含显然错的回答 | 每条显然错句 | 拒答 | 显然错句数比 R0 |
|---|---|---|---|---|
| 训练前 | 36.5% | 0.650 | 26.5% | |
| R0 整段一个分 | 30.0% | 0.485 | 10.0% | — |
| R1 整段，去底噪 + 按错句计数 | 32.5% | 0.445 | 8.5% | −0.040 [−0.117, +0.031] |
| R2 加句子层优势 | 24.0% | 0.340 | 10.5% | −0.145 [−0.236, −0.061] |
| R3 再往前传一句 | **23.0%** | **0.275** | 9.0% | **−0.210 [−0.309, −0.120]** |

R1 和 R0 几乎没差别，R2 一下子拉开：关键不在公式怎么写，而在信号有没有落到具体那一句上。长度、句数、拒答都没有变差。此后 R3 成为所有 RAG GRPO 的奖励。

代码：`train/ans_reward.py`（`group_baseline`、`count_reward`、`sentence_adv`）、`train/ans_grpo.py`（`token_sentence_index`、`token_advantages`）、`tests/test_ans_stepreward.py`、`scripts/remote/run_rwexp.sh`。

### 7.5 GRPO vs SFT

同一批 831 个训练 prompt，比较三种做法（9B 打分，三套验收约 595 条配对回答）：

| | 显然错句数 | 含显然错 | 含任意错 | 拒答 |
|---|---|---|---|---|
| v0 | 0.724 | 40.5% | 47.2% | 36.5% |
| S1：Claude 只改错句，再 SFT（2 轮） | 0.345 | 25.4% | 37.7% | 16.5% |
| S2：v0 每 prompt 采 16 条，按 R3 奖励选最优，再 SFT | 0.701 | 40.7% | 49.6% | 24.2% |
| R3 GRPO 50 步（h3ctl） | 0.385 | 27.9% | 39.5% | 23.0% |
| R3 GRPO 200 步（h3ctl） | 0.145 | 13.3% | 26.1% | 9.1% |

- 一次「Claude 改对再 SFT」≈ R3 GRPO 50 步的效果，拒答更少、回答更长。S1 用的这批 Claude 改对数据，后来就成了核心集（§2.4）的起点。
- **拒绝采样 SFT 基本没减少幻觉**（−0.024 [−0.078, +0.030]），只把拒答降下来了。可能是选出来的「最优」主要靠不拒答和满意度拿分；也可能是自己的样本做一次 SFT，分布基本不动，没有负样本信号。
- S1 加训：3 轮 0.305、4 轮 0.303、6 轮 0.407（过拟合）。而训练目标本身（Claude 修正后的参考回答）只有 0.099 句 / 条。SFT 的天花板远低于学到的 0.30，瓶颈在学习而不在数据质量；GRPO 200 步已比 SFT 最好的低一半，但还没到 Claude 修正目标的水平。

### 7.6 critic 质量对 RAG 的剂量关系

为了直接检验「生成器 → critic → RAG」这条链，我们挑了三档静态指标有显著差异的 critic（显然错 AUC：ref 0.821 / z1500 0.840 / h3ctl 0.852），各用 R3 训 RAG，后来又加了 n1500 一档（0.837，1,500 对 + 自然度过滤，用来把 z1500 和 h3ctl 的两处差别分开）。

| critic（AUC） | 第 50 步 | 第 100 步 | 第 200 步 | 200 步含任意错 | 200 步拒答 |
|---|---|---|---|---|---|
| v0 | 0.725 | | | 47.3% | 36.4% |
| ref（0.821） | 0.349 | 0.225 | 0.166 | 23.3% | 18.1% |
| z1500（0.840） | 0.357 | 0.218 | 0.196 | 28.5% | 12.1% |
| n1500（0.837） | 0.361 | 0.240 | 0.200 | 28.4% | 19.1% |
| h3ctl（0.852） | 0.384 | 0.216 | **0.144** | 26.0% | 9.1% |

（每条回答的显然错句数，596 条配对、300 个原文。）

- 50 步时三档两两全不显著，方向甚至和 AUC 相反：50 步只修掉了所有 critic 都判得出的容易错。
- 200 步时 h3ctl − z1500 −0.052 [−0.086, −0.019]、h3ctl − n1500 −0.055 [−0.091, −0.022]，都显著；n1500 和 z1500 打平。所以自然度过滤没用，问题在量：同门槛下 554 对最好，1,500 对 RL 后变差。
- 排序不是单调的：h3ctl < ref < z1500 / n1500，AUC 居中的那档反而最差。

**被钻空子程度**解释了这个排序。用各档自己的 2B critic 去认 9B 判定的显然错句：

| critic | v0 回答上召回@0.5 | 第 200 步剩下的显然错 | 自己 critic 在剩下的错上召回 | 平均 P 低估 |
|---|---|---|---|---|
| ref | 0.736 | 99 | 0.293 | — |
| z1500 | 0.632 | 117 | 0.214 | 0.049 |
| n1500 | 0.616 | 119 | 0.252 | 0.043 |
| h3ctl | 0.655 | 86 | 0.360 | 0.037 |

训完剩下的错天然偏向自己 critic 漏判的那类，所以召回都掉；可比的是掉多少、剩多少。h3ctl 掉得最少、剩的错最少；z1500 剩下的错只认出 21%，整体低估最多，最容易被策略骗过。这和 RL 结果一致，而静态 AUC 预测不了这一点。

KL 护栏（窗口均值 ≥ 0.10）在第 100 步前后把三档都叫停了，其余护栏都没触发；KL 是正常偏离，不是钻空子，于是统一放宽到 0.2 续训到 200 步。三档几乎同时触发，比较仍是公平的。

代码：`ragtruth/pol9b_cmp.py`、`scripts/remote/run_r3full.sh`、`run_r3eval.sh`、`run_r200c.sh`。

### 7.7 核心集阶段的分段训练（表 2）

核心集阶段的 RAG 从 RAG-SFT 出发，每次 critic 更新后从上一段的 GRPO 检查点接着训 100 步（lr 5e-6，16 prompt × 16，KL 相对新起点，参考回答由新起点重采），而不是从 SFT 重来。三套验收 595 条配对回答：

| 模型 | 含显然错 | 显然错句 / 条 | 含任意错 | 拒答 | 句数 |
|---|---|---|---|---|---|
| RAG-SFT | 25.2% | 0.358 | 35.8% | 27.6% | 3.83 |
| RAG-S1（critic rm1__core，200 步） | 9.8% | 0.106 | 21.7% | 6.0% | 3.81 |
| RAG-S1x（对照：critic r1，从 SFT 重训 200 步） | 11.6% | 0.128 | 21.3% | 5.9% | |
| RAG-S2（critic r1，从 S1 接着训 100 步） | 6.6% | 0.072 | 16.8% | 3.5% | 3.74 |
| RAG-S3-r2（critic r2，从 S2 接着训） | 8.1% | 0.081 | 14.6% | 1.5% | 3.47 |
| RAG-S3-r3（critic r3，从 S2 接着训） | 5.4% | 0.056 | 14.0% | 2.2% | 3.74 |

- 同一个新 critic r1，接着训比重新训少 5.0 个点含显然错 [−7.6, −2.3]。
- RAG-S3-r2 是反面教材：r2 的静态指标更好，RAG 却变差（对起点 +2.5 [+0.7, +4.5]），句数掉到 3.47。策略把错推进了 r2 的长句盲区：r2 在 9B 显然错句上的召回从 0.39 降到 0.31。r3 专门补了长句之后（§4.10）才不再退化，但 r3 对起点 −1.3 [−3.7, +0.9] 也不显著，只是对 S3-r2 显著更好（−2.5 [−4.7, −0.5]）。
- 同一检查点两次独立生成，差异约 1–1.5 个点，所以跨实验比较以「对自己起点」为准。

代码：`scripts/remote/run_loop2.sh`、`run_loop2cont.sh`；结果 `outputs/rt/core/loop2_all_cmp.json`。

## 8. 两轮盲区驱动闭环

闭环是：用 critic 当奖励训 RAG → 按类型看 RAG 犯了什么错、critic 漏了什么 → 针对盲区类型造难样本 → Claude 核实 → 重训 critic → 从上一轮 RAG 接着训。

### 8.1 第一轮：RAG-S3-bf

critic 是 §6.2 的 bfcl，从 RAG-S2 接着训 100 步（tech_share_details 表 8）：

| RAG 模型 | 含显然错 | 显然错句 / 条 | 含任意错 | 拒答 | 句数 |
|---|---|---|---|---|---|
| RAG-S2 | 6.6% | 0.072 | 16.8% | 3.5% | 3.74 |
| RAG-S3-r3（之前最好） | 5.4% | 0.056 | 14.0% | 2.2% | 3.74 |
| **RAG-S3-bf** | **4.7%** | **0.047** | **10.4%** | 1.8% | 3.72 |

- 对自己的起点（RAG-S2 同一次重新生成）：含显然错 −2.9 [−5.5, −0.5]、显然错句 −0.035 [−0.064, −0.010]、含任意错 −4.7 [−7.8, −1.9]，三项都显著。
- 对 RAG-S2 含任意错 −6.4 [−9.5, −3.5]；对 RAG-S3-r3 含任意错 −3.5 [−5.8, −1.3]，显然错持平。
- 句数、长度没变，拒答 3.5% → 1.8%，没有钻空子的迹象。

### 8.2 对照：提升主要来自新 critic，不是多训的步数

RAG-S3-r1 与 RAG-S3-bf 设置完全相同（从 RAG-S2 出发、R3、100 步），唯一区别是奖励模型保持 r1 不换（596 条配对）：

| 模型 | 含显然错 | 显然错句 / 条 | 含任意错 | 句数 |
|---|---|---|---|---|
| RAG-S3-r1 起点 | 6.7% | 0.074 | 15.3% | 3.72 |
| RAG-S3-r1 第 100 步（奖励模型不换） | 7.9% | 0.082 | 14.4% | 3.44 |
| RAG-S3-bf 起点 | 7.5% | 0.082 | 15.1% | 3.72 |
| RAG-S3-bf 第 100 步 | 4.7% | 0.047 | 10.4% | 3.73 |

S3-r1 对自己的起点：含显然错 +1.2 [−1.1, +3.5]、含任意错 −0.8 [−3.8, +2.2]，都没有改善，句数却从 3.72 掉到 3.44，开始合并句子讨好已经被摸透的旧 critic。同样多训 100 步，S3-bf 比 S3-r1：含显然错 −3.2 [−5.3, −1.2]、显然错句 −0.035 [−0.059, −0.013]、含任意错 −4.0 [−6.6, −1.5]，两者起点无差别。

**独立复现。** 开源时在新的 GPU 服务器上，只用发布的数据、LoRA 和 `scripts/repro/r2_rag.sh` 从 RAG-S2 重训了这两组（596 条配对）：新 critic 组 含显然错 3.9% / 含任意错 11.6%（原 4.7% / 10.4%），对照组 5.9% / 13.9%（原 7.9% / 14.4%），句数 3.72 / 3.60（原 3.73 / 3.44）。新 critic − 对照：含显然错 −2.0 [−3.6, −0.5]（显著），含任意错 −2.4 [−4.7, +0.0]（临界）。新 critic 组复现得很好，变化主要在对照组：这次它自己也有改善。

**结论：含显然错上两次独立运行都显著，提升主要来自补过盲区的新 critic；含任意错上一次显著、一次临界。** 原实验对照组「完全没改善」部分来自运行间的随机性，同一设置独立重跑能差约 2 个点，比此前估计的约 1 个点大。

bfcl 的静态指标几乎没变（对 r2 显然错 AUC −0.012 不显著），当奖励却明显有效。我们的理解是：补盲区后 critic 对细微错「有了感觉」，范围偏移里完全看不见（P < 0.1）的从 25% 降到 17–19%，分数哪怕没过 0.5，在 GRPO 的组内比较里也能变成梯度。

代码：`scripts/remote/run_round2_rag.sh`、`run_rag_ctl.sh`、`scripts/repro/r2_rag.sh`；结果 `results/loop2_cont4_cmp.json`、`results/loop2_cont5_ctl_cmp.json`、`results/repro_r2_report.txt`。

### 8.3 第二轮：RAG-S4-rd2

critic 是 §6.3 的 rd2，从 RAG-S3-bf 接着训 100 步（tech_share_details 表 9）：

| RAG 模型 | 含显然错 | 显然错句 / 条 | 含任意错 | 拒答 | 句数 |
|---|---|---|---|---|---|
| RAG-S3-bf | 4.7% | 0.047 | 10.4% | 1.8% | 3.72 |
| S4 起点（S3-bf 重新生成） | 4.5% | 0.049 | 9.8% | 2.0% | 3.75 |
| **RAG-S4-rd2** | **4.0%** | **0.040** | **9.1%** | 1.3% | 4.19 |

对自己的起点：含显然错 −0.5 [−1.9, +0.9]、显然错句 −0.008 [−0.023, +0.007]、含任意错 −0.7 [−3.0, +1.6]，都不显著；拒答 −0.7 显著。句数 3.75 → 4.19、长度不变，策略在把句子拆短（critic 对短句漏判更多），但 9B 没看到错误随之上升。这和 rd2 静态区分度下降一致：第二轮补的多是难段的细微错，critic 学成「更多疑」，当奖励也没带来新的提升。另外，RAG 已经降到 4% 左右的显然错，在 9B 评测的精度下剩下的空间也小了。

两轮合起来（RAG-S2 → RAG-S4-rd2），含任意错 16.8% → 9.1%，−7.7 [−11.0, −4.8]，相对 −46%；含显然错 6.6% → 4.0%，−2.5 [−4.6, −0.7]，相对 −39%。主要收益在细微错上，和补进去的样本以细微错为主相符，大部分来自第一轮。由于第二轮已不显著、收益明显递减，闭环到此停止。RAG-S4-rd2 是数值最好的版本，RAG-S3-bf 是最后一个显著提升的版本。

代码：`scripts/remote/run_rag_s4.sh`；结果 `results/loop2_cont6_cmp.json`。

## 9. 漏判分析

### 9.1 2B critic 为什么漏明显错

**同数据 9B 对照。** 2B GRPO 验收回答 414 句（错 87），同一份训练数据训出的 2B / 9B critic：明显错 30 句，2B 判出 6、9B 判出 24（9B 判出 2B 漏的里张冠李戴 8/11、矛盾 7/10）；轻微错 57 句两者都漏 38，确定性 / 范围偏移 26 句里两者都漏 21；非错误误报都是 6/327。明显错不难，同数据 9B 能判出八成，是 2B 的能力问题，加上这批回答本来就是对着 2B critic 优化出来的；轻微错是标准问题，训练标签（RAGTruth 宽松口径 + 有依据行里约 10% 的同类藏错，§2.2）教的就是「这类偏移不算错」。

**是不是找不到证据？** 同一句分别给完整原文和只给 Claude 标的证据段：

| | clear 判出 | 非错误报 | clear AUC | 误报 5% 召回 |
|---|---|---|---|---|
| 2B，完整原文 | 15% | 3% | 0.81 | 0.34 |
| 2B，只给证据段 | 52% | 17% | 0.77 | 0.24 |
| 9B 金标 critic，完整原文 | 64% | 4% | 0.93 | 0.66 |
| 9B 金标 critic，只给证据段 | — | — | 0.86 | — |

只给证据两个都更差，判出与漏判的原文长度也没有差别。问题不在长原文里找证据，而在 2B 比对人物 / 关系的能力。

**告诉它张冠李戴是什么。** 张冠李戴 / 混合段落错 42 句（clear 27）：基线 critic 3/27；system prompt 加定义 5/27（单字母微调模型基本不读新说明）；2B 底座只开思考 8/27、加定义 + 思考 9/27（误报 3/603）；9B 底座加定义 + 思考 15/27。起作用的是「先逐步核对」，定义只略减误报；2B 逐步核对后仍漏三分之二，没有继续做思考核对器。

**拒答**是标签问题，见 §4.6。

代码：`ragtruth/evidence_probe.py`、`ragtruth/attr_probe.py`。

### 9.2 核心集 critic 的盲区形态

在 cap3 上看 rm1__core：显然错 179 句漏 99（P < 0.5）。漏掉的分数分布 < 0.1 占 21%、0.1–0.3 占 43%、0.3–0.5 占 35%，而没错句子的 P 中位数 0.076。漏掉的显然错 52% 排在没错句子的前 20%。所以「高置信地认为没错」的盲区只占约五分之一，大部分是「有点怀疑但没到阈值」，这正是后来按 critic 0.1–0.5 取样的依据。把显然错召回拉到 80% 的代价很高：rm1__core 阈值要降到 0.150，没错句子误报 28%。

漏判机制分布（金标 critic 漏掉的 339 个错误）：范围 / 确定性偏移 35%（该机制漏判率 76%）、近义 15%、张冠李戴 13%、直接矛盾 13%、跨段拼接 11%、模糊附加语 1%、添加具体事实 1%。而 2B 生成器的真错里模糊附加语占 17%、添加具体事实 12%，跨段拼接只有 4%。**合成数据和 critic 漏判的分布错位**，这是 §4.9 里随机加样本没用的一个原因。

代码：`scripts/analysis/blind_dist.py`、`ragtruth/critic_cap3.py --by_type`。

### 9.3 第一轮之后还漏的显然错

bfcl 在 cap3 上阈值 0.5 漏判显然错 69 句：

- 按机制：范围偏移 13/20（65%）、近义偏移 7/11（64%）、张冠李戴 20/44（45%）；跨段拼接、直接矛盾各约 30%。
- 长句已经不是盲区：≥ 25 词漏判率 24%，< 15 词 44%。
- **和原文字面重合度高的更容易漏**：句子 4-gram 有 30–60% 来自原文的漏判率 60%，< 30% 的 36%。

读了漏得最严重的 25 句（P < 0.15），几乎都是「整句大体照抄原文，只改一处」，可以归成五种更细的模式：事件 / 对象错配（赢了 HOH 后提名写成赢了 POV；首映的是预告片写成影片首映）；角色 / 关系颠倒（机构需要国会拨款写成国会需要经费）；限定词丢失（aims to → will、去掉 on average、「唯一一位传染病医生」→「唯一一位医生」）；时间视角错位（「当时 12 岁」写成「一个 12 岁的女孩」）；单复数（一个据点 → 多个据点）。这类错，自由改写的生成器基本造不出来。

代码：`scripts/analysis/clear_miss_an.py`。

### 9.4 早期 RM1 的漏检盲审

RM1 在 ++ 严格口径 649 个正例上阈值 0.5 漏 317 个，分层抽 100 条 Claude 盲审：不是错误 24、轻微 54、明显 22。RM1 概率 < 0.05 的 35 条里 14 条不是错、只有 3 条明显；0.2–0.5 的 25 条里 8 条明显。明显错误 22 条以归属错和与原文矛盾为主，16 条只需对照原文一处。这次盲审第一次提示我们：测试集比训练标签多出的大量轻微错误，可能是训练标签没教过的，这引出了 §2.2 里严格口径下的训练负例抽查。

代码：`ragtruth/miss_analysis.py`。

## 10. 两个判断与未解决的问题

### 10.1 两个判断

**现有的错误合成方法不足以继续扩充盲区。** 它能补上 critic「拿不准、但能被人确认」的那一层，第一轮闭环就是靠这个见效的。证据：生成器迭代四轮，难样本一直停在每 2,048 条约 40 条；要求的类型和实际造出的只有约 31% 一致；第二轮往难段挖，挖到的多是和忠实改写只差一点的细微错，critic 学成「更多疑」；critic 真正漏掉的显然错（高重合、只改一处，§9.3），自由改写造不出来。

**奖励模型的静态指标和 RAG 最终效果不是绝对一致的。** 前后撞见了三次：三档 critic（AUC 0.821 / 0.840 / 0.852）训 RAG 200 步，AUC 居中的那档最差（§7.6）；第一轮 bfcl 静态 AUC −0.012（不显著），当奖励却让 RAG 显著变好（§8.2）；第二轮 rd2 静态 AUC 显著变差，当奖励 RAG 却没有变差（§8.3）。和 RL 结果更一致的是「被钻空子程度」：训练后剩下的错误里，critic 自己还能认出多少。评价奖励模型时，静态 AUC 只能当门槛，还要加上短程 GRPO + 独立评测，或者被钻空子程度。

### 10.2 还没做或没验证的事

1. **系统化的错误体系**。现在只有 9 个机制类。设想是分层（粗类 → 机制 → 子类），子类从真实错误里归纳（例如 §9.3 的五种模式），每个子类一张卡片（定义、正反例、适用条件、造法、核实要点、指标、样本库、版本），用来驱动评测、补样本配额、critic 回归门槛和生成器出题。尚未开始。另一个理由来自造样本："真错、自然、critic 拿不准"三个目标互相拉扯，自由造错时三者同时满足的只有约 1.4%（§5.9），指定 9 类之一后 2048 条里也只有约 40 条、64 组提示里 42 组为零（§5.12），GRPO 没有组内差异可学。细化到子类并只在合适的句子上出题，是让每道题都有机会命中的办法（判断，未验证）。
2. **适合度模型**。指定错误类型后生成器只有约 31% 遵守，很多句子根本不适合这类错（没有数字却要造数字错；添加事实在盲区里几乎造不出对口样本；直接矛盾一旦造难就变成别的类型）。需要先挑出适合改写的（句子，类型）组合，第一版可用规则，之后用生成成功率训模型。
3. **其他任务**。只在 RAGTruth 的问答和摘要、2B 模型上做过。智能搜索（多来源、噪声、来源冲突）和 Agent（多步工具调用轨迹）还没碰。
4. **核实成本**。critic 盲区里的样本只能靠人（现在是 Claude）确认，难段里只有约一半是真错，对照已证明省不掉。
5. **评测本身的局限**。Claude 和真人的一致性没测；9B 评测器在大的变化上和 Claude 一致，但在 RL 训练后的输出上只是中等可靠（显然错 AUC 0.82，不比最好的 2B critic 强），绝对比例约为 Claude 的六成，几个点的小差距方向没有保证（§1.5）；9B 只判对错、不给类型，RAG 按类型的错误分布还算不出来；没有多种子重复，差异靠 bootstrap 区间判断，而整个训练独立重跑能差约 2 个点（§8.2 的复现）；RAG 显然错降到 4% 左右后，在 9B 的精度下很难再测出显著差异。

## 11. 试过但没用的方向

这些方向在正文里多有细节，这里只列一句话结论和关键数字，方便快速查。

- **挑 critic 识破不了的合成样本**（9B）：和随机同条数相比召回差 −0.005 [−0.019, +0.009]，等于把阈值调松一档（§4.1）。
- **多轮 critic 循环挖难样本**：第 2 轮召回只增 0.002，下一轮难样本率从 20% 掉到 5–10%（§4.2）。
- **生成器—判别器 DPO 循环（GAN 式）**：DPO loss 0.692，几乎没学；第 2 轮 critic 没有额外提升（§5.2）。
- **按「难 + 真」综合分 DPO**：循环内指标翻倍，金标召回显著下降，收敛到「句尾挂目的短语」（§5.4）。
- **定向改法合成**（张冠李戴、拼接等清单）：对清洗后的 critic 无显著增益，误报 +24 句（§4.3）。
- **用 35B 同提示词复判一次来过滤**：两次判定高度相关，筛不掉错样本（§5.1）。
- **RM3 当正确性门槛**：在已过门槛的边界样本上 AUC 0.51，调高门槛纯度只从 79% 到 81%（§5.8）。
- **生成器奖励加保底分**：明显错比没过门槛更划算，critic ≥ 0.9 的比例 55% → 72%（§5.12）；全记 0 又让「不造错」成退路（a8，§5.8）。
- **组内排名的难度奖励**：强化的是过门槛，0.1–0.5 条数 29 → 29（§5.12）。
- **critic 区间门槛直接进生成器训练**：几乎没有正样本，合格率 5.5% → 6%（§5.12）。
- **合成边界样本 + 清洗（h2）**：只回到基线水平，边界区误报不降（§4.6）。
- **复核、限定边界、多样性、自然度过滤**：同条数下都没有额外收益（§4.7）。
- **大量合成数据**：6,000 对显然错 AUC 0.820，比 1,500 对低 0.020，++ 也开始下降（§4.7）。
- **9B 生成器**：解释更好，真错率不变（§5.10）。
- **给 sev 加逐词改动标记**：真错 AUC −0.007（§5.10）。
- **h2 critic 当 RAG 奖励**：与基线 critic 的差在 ±5 个点内（§7.3）。
- **拒绝采样 SFT**：显然错句数 −0.024，不显著（§7.5）。
- **长句增强（r3）**：堵住了合并句子的漏洞，但 Claude 金标显然错 AUC −0.022（§4.10）。
- **2B 思考核对器**：张冠李戴 clear 判出 3/27 → 9/27，仍漏三分之二（§9.1）。
- **「骗过 critic + 过 sev」的 gated / add 生成器**：所谓盲区样本 Claude 只确认 24% 是真错（配对原句 92% 正确，说明不是 Claude 太严）；真错率随盲区深度单调下降（critic P < 0.1 只有 14%）。补进 critic 后整体召回和金标 AUC（0.830 → 0.810）都变差。奖励坍缩成「造 sev 会误判的非错句」（§5.10）。

## 12. 踩过的坑

### 12.1 方法上的坑

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 更严格的 critic 精确率反而更低 | RAGTruth 人工标签漏标多，多报的大多是真幻觉 | 以召回为主，精确率只用 Claude 修正后的标签估 |
| 用 35B 修正标签后结果偏乐观 | 单方面复核等于默认 35B 是对的 | 对称复核或引入第三方（Claude） |
| 直接加合成数据召回变高 | 同时改变了训练集正负比例 | 对照组控制条数和比例，设 random 组；或者比判出同样多条时的召回 |
| 「critic 识破不了」的样本加进去没用甚至有害 | critic 越强，识破不了的样本里噪声越多；critic P 极低的合成样本多半根本没错 | 挑样本只取 critic 拿不准的区间（0.1–0.5），并经 Claude 核实 |
| 生成器奖励「骗过 critic」造出一堆非错句 | 最容易骗过 critic 的「错误」就是没错的句子；sev 和 critic 同是 2B，在盲区一起失明 | 不单调奖励骗过 critic，按 critic 区间给难度分；入库必须外部核实 |
| 固定 recall@0.5 看起来救回很多盲区 | 阈值漂移虚涨 | 用同误报率或判出同样多条的口径比较 |
| 只看显然错 AUC，范围偏移的提升看不见 | Claude 把大多数范围偏移标为细微 | 固定三个口径一起看：显然错、任意错、按类型 |
| 抽 10 条看到「九成是真错」，以为可以不核实 | 样本太少；放大到约 100 条只有三分之二 | 核实与否做对照，不靠小抽样定流程 |
| 往难段多挖，critic 变「多疑」 | 难段真错多是和忠实改写只差一点的细微错 | 难样本不是越多越好；按区分度而不是阈值召回判断 |
| 静态指标更好的 critic，RL 后不一定更好 | RL 会把错推进 critic 的盲区（长句、合并句、拆短句） | 看被钻空子程度、做短程 GRPO + 独立评测；每次评测盯句数和长度 |
| 按回答 bootstrap 区间偏窄 | 同一原文的多条回答相关 | 按原文聚类抽样 |
| 生成器自报的解释把 sev 带偏 | 理由像样但不成立，sev 跟着理由走 | sev 输入去掉生成器的类型、证据、理由 |
| 生成器奖励里的多样性被钻空子 | 改法名是模型自填的开放字符串，新名字计数为 0 | 改法封闭到标准名 + other；多样性改成窗口计数或按位置计 |
| 定向改法用到了测试集的错误分析 | 类别来自 ++ 错误分析 | 提示里只写类别，不用测试集的具体例子 |
| 种子组装时删掉相邻错句，改对句和上下文接不上 | 改对时没看上下句 | 改对时放回整条回答，按上下句一起复核 |
| 同一 RM 不同代码路径打分对不上（0.47 vs ≥ 0.71） | 一处给改写前的原回答，一处给已替换的回答 | 统一提示格式；生成器奖励调用 sev 必须用 `sev_rm.prompt` 同样的格式 |
| 不同版本 RM2 的分数被拿来比较 | 每版 RM2 的合成负例来自不同生成器 | 比较生成器时用同一个 RM2，且只看它训练集外的原文 |

### 12.2 训练与推理

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 0.6B SFT 显存溢出到共享内存 | Base 模型 + 完整 logits 的 NLL | 改用 instruct 模型 + 分块 NLL |
| Qwen3.5-9B 训练 OOM | 缺线性注意力 kernel；eval 模式关掉了梯度检查点 | 装 flash-linear-attention；调用 `peft.train()` |
| 合并出来的判别器就是基座（留出 AUC 0.62） | TRL 按多模态结构加载，适配器参数名带 `language_model`，合并脚本按纯文本结构加载，参数名对不上，PEFT 只给警告 | `merge_lora` 按适配器参数名选加载结构，并检查文本层 lora_B 非零 |
| vLLM 拒绝加载 LoRA | 适配器里带视觉塔参数（all-linear 也挂到了视觉塔） | 去掉 visual.* 参数；多 LoRA 服务一律用 `scripts/remote/serve_loras.sh` |
| vLLM 加载 9B 合并权重失败 | 缺 chat template、被当成多模态 | 从基座复制分词器和处理器文件，限制图像 / 视频输入为 0 |
| 数据切分重跑后不一样 | 遍历 `set` 的顺序随 PYTHONHASHSEED 变 | `sorted(...)` + `PYTHONHASHSEED=0` |
| MiniCPM 第 1 步截断比例 22% | vLLM 自己分词加了 BOS，训练侧不加 | 直接发 token id，两边同一份（降到 0.6%） |
| 采样和训练的概率不一致 | vLLM 沿用 generation_config 的 top_p 0.95 | 显式 top_p 1.0、top_k −1 |
| 续训后每次生成都重载 LoRA，步时间翻倍 | `load_inplace=True` 留在 LoRA 请求上 | 已加载时先卸载再加载 |
| 训练线程 GPU 利用率低 | 训练每步从 Python 发几十万个小 kernel，同进程的采样 / 打分线程抢 GIL | 采样、打分、快评放子进程；再加流水线（每个 prompt 生成完立刻打分） |
| 2B 训练 GPU 利用率低 | 42 层窄模型、每条回答单独过大词表输出层，小块调度开销大 | 输出层拉平有效 token 按 2048 分块 |
| 训练卡上重复算 prompt | 同一 prompt 的 8–32 条回答各算一遍前缀 | prompt 共享（`train/prefix_share.py` / `prefix_share_llama.py`），逐层取状态、completion 分批接上反传；梯度与整段拼接的差在 bf16 噪声以内 |
| Qwen3.5 前缀缓存命中低 | 线性注意力层按 Mamba 缓存，只在 528 token 块边界存状态 | 要改 vLLM 内部才行，未做 |
| 同一回答的 RM 打分都命中不了缓存 | 几条请求同时发，都还没算完 | 先打 1 条，再并发其余 |
| 16 个 critic 逐个打分很慢 | 每次只挂一个 LoRA、并发低 | 一次挂上全部 LoRA、请求混发（`critic_score_multi.py`），约 8 倍，逐句差异 ≤ 0.006 均值 |
| 从共享盘直接加载权重极慢 | 按需随机读 safetensors，网络存储吞吐低 | 先拷到本地盘；训练只读写本地盘，共享盘后台同步（`bg_sync.sh`） |
| 重构时误删了训练入口函数 | 验证路径不走这些函数 | 单测加入口函数检查；长跑前至少跑通一次完整 run，切换后盯第一步 |
| 存完模型进程不退出，被判失败 | 原因未查明 | `train/sft.py` 存完写 SAVED 标记，最后 `os._exit(0)` |

### 12.3 远程脚本与基础设施

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `pkill -f 脚本名` 把自己杀了 | 执行这条命令的 shell 命令行里也有这个字符串 | 写成 `pkill -f '[r]un_x.sh'`；停止和重启分两次调用；常驻服务用 pid 文件 |
| 带保活循环的脚本卡死、看门狗也不关机 | 裸 `wait` 连保活子进程一起等，而保活要等脚本退出才结束；保活一直刷标记 | 记下保活进程 id，只等其他作业；判断卡住要看日志时间戳 |
| 正在跑的脚本读不到后半段，报 `error reading input file` | 别的机器开机时解压代码包并 `sed -i` 去 \r，把每个 .sh 换成了新文件，而 bash 是边执行边读脚本的 | 先解压到本地暂存目录处理，再 `rsync -c` 只替换内容变了的文件；长跑脚本拷到本地再执行 |
| 上传的脚本报语法错误 | Windows 写出的 CRLF | 上传后转 LF |
| Git Bash 把 `/root/...` 改写成 Windows 路径 | MSYS 路径转换 | 远程相关命令统一带 `MSYS_NO_PATHCONV=1` |
| SSH 断开后后台任务被杀 | 进程挂在会话下 | `setsid nohup`，不分配 pty |
| 用 `ls 文件 \| grep done` 判断文件存在，误触发 | 文件不存在时的报错里也有 done | `test -f 文件 && echo 唯一标记` |
| 等待条件被上一轮残留的完成标记误触发 | 只看日志里有没有标记 | 「进程已退出 + 最后一行是标记」 |
| `grep "X_DONE name"` 前缀匹配到了别的任务 | 名字是另一个名字的前缀 | 精确匹配（名字后接空格或行尾） |
| 下载结果时把本地完整文件截断 | paramiko 的 get 先清空本地文件 | 先下载到 .part，远端更小时不覆盖 |
| 结果没下载就关机 | 关机命令和下载写在同一条命令里，下载失败照样执行 | 关机放在下载成功之后（`&&`） |
| 强杀 vLLM 后显存仍被占 | `VLLM::EngineCore` 成了孤儿进程 | 停 vLLM 时连同 EngineCore 一起杀 |
| 上一组评测的 vLLM 没关，下一组训练 OOM | 服务常驻占显存 | 每段任务前先停服务、等显存释放 |
| 远端缺本地才有的数据文件，流程中途退出 | 标注文件只在本地 | 标注和名单放 `configs/data/` 随代码包上传 |
| 有依赖的任务让机器空等 | 固定分工，一台等另一台的结果 | 共享队列：每行「名字\|依赖\|命令」，空闲机器用 mkdir 原子领第一个依赖已满足的任务（`queue_worker.sh`） |
| 多机分片时重复判同一批样本 | 各片只在启动时读一次其他片的输出 | 改成静态分片，或判前实时检查占位文件 |
| 续训后 GPU 利用率记录被覆盖 | 恢复时日志文件用 "w" 打开 | 改成追加 |
| 跨机传 LoRA 很慢 | 跨区上传带宽低 | 主线程只存内存盘，后台线程经共享盘中转，推理机拷到内存盘再热加载 |
| 抢卡脚本 SSH 断开后直接退出，机器空转 | 上传代码时异常没有重试 | 挂监控后确认远程进程真的在跑 |
