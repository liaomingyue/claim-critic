# 结果与结论（截至 2026-11-04）

本文从 `docs/experiment_log.md`（按时间顺序的完整记录）整理而来，按组件汇总现状、关键数字和结论。数字都取自日志原文；日志里没有的数字这里不写。细节、命令和踩坑请回到日志查对应日期。

## 缩写与口径

| 缩写 | 含义 |
|---|---|
| 2B | MiniCPM5-2B（openbmb/MiniCPM5-2B），当前全部训练用模型的底座 |
| 9B | Qwen3.5-9B（LoRA），早期主力；现在只用于不进训练的评测和监控 |
| 35B | Qwen3.5-35B-A3B-GPTQ-Int4，早期用于补写、合成和判有效 |
| RM | 奖励模型（reward model）。本项目的 RM 都是「单字母选项分类」：只输出一个选项字母，读选项概率，在校准集上用一个全局温度 T 校准 |
| RM1 / critic | 幻觉检测器：输入原文 + 整条回答 + 待查句，选项 A 无幻觉 / B 冲突（conflict）/ C 无依据（baseless），P(有幻觉) = P(B) + P(C) |
| RM2 | 真实性（自然度）判别器：这句错误是回答模型自己写的（自然），还是事后改出来的（合成） |
| RM3 | 合成错误正确性判别器：A 合格 / B 有错但解释不对 / C 其实没改出错 / D 原句本身有错 |
| sev RM | 严重程度 RM（6 选 1，见 §6） |
| GRPO / DPO / SFT | 组相对策略优化 / 直接偏好优化 / 监督微调 |
| AUC / ECE | ROC 曲线下面积 / 期望校准误差 |
| clear / minor | 明显错误 / 轻微错误（金标规范 `docs/gold_standard.md` 的 severity） |
| 严格口径 | 用户 2026-10-29 定：边界不明确的按有错处理，含糊的评价 / 目的附加语、改变确定性或范围的近义替换都算错，拿不准算错 |

评测集：

- **RAGTruth++**（`test_pp.jsonl`）：402 条回答、2,306 句，只有 QA 和 Summary。「严格」= ++ 全部标签；「有效」= 去掉 ++ 新增里 Claude 判 mild / nitpick / meta 的句子（2026-10-29）。
- **金标评测集**（2026-11-01）：同 402 条回答由 Claude 按金标 v1 重标，错误 705 句（明显 321）。区间按原文抽样做配对 bootstrap。
- **验收集**：同 100 个原文-种子，生成后由 Claude 按金标 v1 标注（每组约 100 次调用），用来比较回答 GRPO 前后。2026-11-03 又从 RAGTruth 原版测试集另取 100 个原文，合计 200 条 2B GRPO 回答（800 句，错 193、clear 75），用来比较 critic。

## 1. 项目目标与循环

### 1.1 循环

```
错误生成器造「当前 critic 的边界错误」
   → 判是否真错（RM3 / 严重程度 RM）且自然（RM2）
   → 加入 critic 训练集
   → critic 检测能力提升
   → critic 作为回答 GRPO 的奖励，提升 RAG 生成的忠实度
```

用户 2026-11-03 定：循环唯一的任务是挖 critic 的边界错误 → 核实真实且自然 → 加进 critic 训练集；以**明显错误的召回**评判。

### 1.2 约束

- **全 2B**：进奖励的模型、进训练数据筛选的门槛全部用 2B（2026-11-02 定；2026-11-04 再次明确「9B 不能用于离线筛选入库样本」）。
- **9B 只用于不进训练的评测 / 监控**（如 9B 金标 critic `rm1__rm1_gold_9b` 补打评测样本）。
- **Claude 用于标注和验收**，预算紧：训练内评测不用 Claude，每次调用前要用户同意，简单标签 10–20 条一批。
- 评价以召回为主（2026-10-27 定）；精确率只能按 Claude 修正后的标签估计，因为 RAGTruth 人工标签漏标多。

### 1.3 早期四个问题（2026-10-26）

GRPO vs SFT、合成 vs 人工、critic 循环挖难样本、人工修正的增益。前三个月的实验大多在回答第 2、3 个问题，结论见 §3、§7 和文末。

## 3. (a) critic（RM1）：数据、训练与标签问题

### 3.1 现状

- **进回答 GRPO 奖励的 2B critic**：`rm1__mcgold`（数据同 9B 的 `rm1__rm1_gold_9b`：训练 5,817 条，A 3,724 / C 1,290 / B 803）。
- **候选新版**：`rm1__mcgold_h2`（清洗过的边界合成样本）、`rm1__mcgold_ref`（拒答标签修正）。下一轮回答 GRPO 计划用 h2（`run_grpo_h2.sh`）。
- **9B 监控 critic**：`rm1__rm1_gold_9b`（9B 金标 critic，只打分不进训练）。

- 单字母分类和生成式 critic 召回相当、精确率高约 0.08–0.10（2026-10-30），之后全部改成单字母 RM。
- 第一次在金标和 9B 留出集上同时显著提升排序的是「加入目标模型自己的回答 + Claude 标注」（2026-11-02），不是合成数据。

### 3.3 2B critic 版本对比（RAGTruth++ 2,306 句）

在 200 条 2B GRPO 验收回答（800 句，Claude 标注）上（2026-11-03）：

| | 基线 | h1 | h1ctl | h2 | h2n |

| 整体 AUC | 0.733 | 0.729 | 0.741 | 0.749 | 0.723 |

### 3.4 边界样本 h1 / h1ctl / h2 的结论（2026-11-03）

- h1 加进去的 1,500 条「错句」，Claude 抽 90 条只有 69 条（77%）是真错，23% 是忠实改写、合理概括或省略。这约 350 条错标正好解释了边界区误报上升。
- 清洗（h2）比同条数不清洗（h2n）好：段内 AUC +0.04、整体 +0.026，把 h1 的区分度损失补回来了。
- 但 **h2 没有超过基线**：边界区误报没降（h2 21 / h2n 21），段内区分度只回到基线水平；随机取合格样本的 h1ctl 一样好。
- 结论：标签噪声是 h1 变差的原因，但不是边界区分不开的主要原因。合成的边界错句没有教会 critic 区分真实回答里的边界错和正确改写。

### 3.5 标签问题

**A 行藏错**（2026-11-03）：`rm1__mcgold` 训练集 A（忠实）3,724 条，按来源抽 220 条 Claude 严格口径盲判：

| 来源 | 藏错 |
|---|---|
| human（RAGTruth 原版人工） | 11/100（11%） |
| synth（合成里没改的句子） | 7/40（18%） |
| gold（Claude 金标） | 2/30（7%） |
| b9（9B 回答，Claude 单轮） | 3/50（6%） |
| 合计 | 23/220（10.5%），**全部是轻微错误** |

- 类型集中在范围夸大、加评价、去掉不确定性、限定条件丢失，正是 2B GRPO 回答漏检的主体（基线 P < 0.1 的 88 句错里 certainty_or_scope_shift 30 句）。
- 用 critic 自己的分数找这些藏错效果有限：P(错) = 1 − P(A) 的 AUC 2B 0.717、9B 0.781；多数藏错分数 < 0.15（9B 16/23）。

**拒答标签**（2026-11-04）：
- 2B GRPO 验收回答里基线 critic P < 0.1 的 30 句 clear 中，8 句是原文能回答却说「Unable to answer based on given passages.」；22 句拒答（错 13）基线一句没判出。
- 训练集 30 句拒答有 25 句标 A；按拒答 RM 的 Claude 标注，b9 的 16 句里 10 句原文能回答。
- 拒答评测（193 条拒答）上基线 2B 判错 0%（P 恒 0.012），9B 金标 critic yes 类 5%：两者都被标签教成「拒答不算错」。
- 修正版 `rm1__mcgold_ref`：10 句能回答的拒答 A → B，加 refuse 训练切分原文各一条拒答（B 399、A 114）。拒答评测判错 yes 97% / partial 83% / no 1/7，RAGTruth++ AUC 基本不变（0.855 vs 0.859）。

### 3.6 遗留问题

- A 行约 10% 轻微藏错没有清理；按 9B 前 30% 让 Claude 复查约 75 次可覆盖约 70%（2026-11-03 估算，未做）。
- h2 和 ref 两项修正还没合并成一个 critic。
- 合理拒答的补样本等回答 GRPO 里出现「硬答」再做（2026-11-04 用户定）。

## 4. (b) 2B critic 漏检诊断（2026-11-03 至 11-04）

问题：2B critic 为什么漏明显错误，是看不到，还是认为「这不算错」？

### 4.1 同数据 9B 对照（grpo300 验收回答 414 句，错 87）

| | 2B 判出 | 9B 判出 | 说明 |
|---|---|---|---|
| 明显错 30 | 6 | 24 | 9B 判出而 2B 漏的 18 句：张冠李戴 8/11、矛盾 7/10 |
| 轻微错 57 | — | — | 两者都漏 38；确定性 / 范围偏移 21/26 两者都漏 |
| 非错误误报 | 6/327 | 6/327 | |

- **明显错不难**：同数据 9B 能判出八成；2B 漏是能力问题，加上这批回答来自对着 2B critic 优化的 GRPO 策略，剩下的正是它的盲区。
- **轻微错是标准问题**：两个模型都漏，训练标签（RAGTruth 宽松口径 + A 里约 10% 同类藏错）教的就是「这类偏移不算错」。

### 4.2 证据段探针（`ragtruth/evidence_probe.py`，775 句，clear 67）

| | clear 判出 | 非错误报 | clear AUC | 误报 5% 时召回 |
|---|---|---|---|---|
| 2B，完整原文 | 15% | 3% | 0.81 | 0.34 |
| 2B，只给证据段 | 52% | 17% | 0.77 | 0.24 |
| 9B 金标 critic，完整原文 | 64% | 4% | 0.93 | 0.66 |
| 9B 金标 critic，只给证据段 | — | — | 0.86 | — |

结论：问题**不是**在长原文里找不到证据（只给证据两个模型都更差），而是 2B 比对人物 / 关系的能力不够。另外，判出与漏判的原文长度没有差别（中位 2.6k / 2.5k 字符）。

### 4.3 张冠李戴定义 / 思考探针（`ragtruth/attr_probe.py`，张冠李戴 / 混合段落错 42 句，clear 27；非错 603）

| 设置 | clear 判出 | 误报 |
|---|---|---|
| 基线 critic，原 prompt | 3/27 | 15/603 |
| 基线 critic，system prompt 加定义 | 5/27 | 15/603 |
| 2B 底座，只开思考 | 8/27 | 5/603 |
| 2B 底座，加定义 + 开思考 | 9/27 | 3/603 |
| 9B 底座，加定义 + 开思考（max_tokens 12288） | 15/27 | 5/603 |
| 9B 金标 critic 单字母（同句，张冠李戴子集） | 16/20 | — |

结论：单字母微调模型基本不读新说明；起作用的是「先逐步核对」，定义只略减误报。2B 思考后仍漏三分之二；微调后的 9B 不思考也行。用户 2026-11-04 决定 2B 思考核对器先不做。

### 4.4 遗留问题

- 漏判的明显错约一半分数 < 0.1（与原文矛盾、确定性 / 范围偏移为主，critic 完全不知道），一半在 0.2–0.5（张冠李戴为主，h1 重训主要帮的是这部分）（2026-11-03）。前者靠合成边界样本补不上。

## 5. (c) RM3：合成错误是否真错

### 5.1 现状

- 2B 版 `rm3__mc`（RM3 数据换 2B 底座，2026-11-03）：校准集 AUC 0.94、ECE 0.062、T=1.3、recall@0.5 0.83、precision@0.5 0.82。
- `rm3__mc_v2`（+ 504 条 Claude 判过的 h1 合成错句）：有提升但仍弱，未替换。
- 门槛实际正在被严重程度 RM（§6）取代。

### 5.2 历史（9B / 35B 时期）

| 日期 | 方法 | 和 Claude 的一致率 / 精度 |
|---|---|---|
| 2026-10-29 | 35B 思考 v1 | 19% 写到上限无结论；四分类 63%、两档 72% |
| 2026-10-29 | 35B v3（严格口径）vs Claude v3 | 四分类 77%、两档 83% |
| 2026-10-30 | 35B v5（怀疑式四步审查） | 判合格的 112 条 Claude 同意 109（97%，在用来改提示词的样本上，偏乐观）；新抽样救回样本 88% |
| 2026-10-30 | RM3 9B 单字母（评测 358 条全 Claude 标签） | AUC 0.894、ECE 0.119、P 0.912、R 0.758，T=1.65 |

关键发现（2026-10-29）：35B 判有效、critic 4 次全没识破（p = 0）的 43 条里 27 条（63%）其实没错。**critic 完全识破不了的样本，多半是判有效的模型错了。**

### 5.3 RM3 在边界样本上失效（2026-11-03）

504 条 Claude 判过的合成错句（已过门槛 0.7，0.3–0.5 段占多数）：

| 打分 | 对 Claude 真错 / 不是错的 AUC |
|---|---|
| RM3 P(A+B) | 0.51 |
| RM3 P(A) | 0.46 |
| RM2 P(自然) | 0.42 |
| 2B critic | 0.57 |

门槛 0.7 → 0.9 只留 30%，纯度 79% → 81%。**在已过门槛的样本上 RM3 等于随机，调高门槛没用，要改的是 RM3 本身。**

`rm3__mc_v2` 结果：原 RM3 测试集 AUC 0.852（`rm3__mc` 0.860），基本持平；test_synth（真错 115 vs 不是错 20）P(A+B) AUC 新 RM3 0.634（1 − P(C) 0.690），门槛 0.7 时纯度 87%。不是错的样本只有 20 条，误差约 ±0.1。

### 5.4 提示词格式不一致（2026-11-04 定位）

- RM3 训练（`rm_data rm3`）和造数据打分（`gen_target_data harvest`）给 `audit_synth.render` 的 `rec["sentences"]` 都是**改写前的原回答**（另列 Original / Rewritten 两行）。
- `ragtruth/rm3_v2.py`（build 和 score）和 `ragtruth/sev_rm.py` 用的是 harvest 的 context，即**已经替换成改写句的回答**。
- 后果：同一个 `rm3__mc` 重打 test_synth 平均 0.47，而 harvest 存的分都 ≥ 0.71。
  - rm3_v2 里「旧 RM3 AUC 0.457」是格式错位的结果，同格式应以 harvest 存的 0.549 为准；`rm3__mc_v2` 的训练集混了两种格式。
  - sev__mc 的新数据和测试都用改后回答，内部一致；和旧 RM3 的比较用的是 harvest 存的分（原格式），比较公平。
  - 以后在生成器奖励里调用 sev RM，必须用 `sev_rm.prompt` 同样的格式（改后回答）。

### 5.5 遗留问题

- `rm3__mc_v2` 需要按统一格式重建训练集才能下结论。

### 7.2 RM2 为什么这么好分（2026-11-03）

- 表面特征（长度、照抄原文、位置、任务、数字、词袋）AUC 只有 0.60–0.61。
- P(自然)：2B 任意句 0.93、2B 真错 minor 0.86、clear 0.67、合成 0.09。一部分信号是「错得明显」（合成一侧过了 RM3 ≥ 0.7，几乎全是 clear），一部分是生成器自己的写法：动数字 22.5% vs 8.5%、几乎换整句 20% vs 10%，还有拼接留下的语病。
- 补上真错后仍然好分（mcgen3），剩下的信号是生成器的写法。
- RM2 很尖：合成样本 P(自然) 分位 10/25/50/75/90 = 0.0008/0.0017/0.004/0.018/0.35。用对数几率映射拉开数值，不另外训软（2026-11-03）。

### 7.3 RM2 和 Claude 是否同向（9B 时期，2026-10-31）

RM2 ≥ 0.5 的样本 Claude 95% 认为真实，< 0.1 的 81%。按句长分解，RM2 分数上涨不是靠句子变短。

### 7.4 遗留问题

- 每换一版生成器，RM2 的合成负例就要跟着换，否则新生成器的分数高可能只是「不像旧生成器」（2026-11-03 注意事项）。
- 2026-11-03 的 rm2score 误用了 `rm2v2__mcgen2` 给第三版打分，不同版本的 RM2 分数不可比。

| vLLM 沿用 generation_config 的 top_p 0.95 | 显式 top_p 1.0、top_k −1，采样和训练概率一致 |
| `load_inplace=True` 留在 LoRA 请求上，每次生成都重载 | 已加载时先卸载再加载 |
| 遍历 set 的顺序随 PYTHONHASHSEED 变，数据切分不可复现 | `sorted(...)` + `PYTHONHASHSEED=0` |
| `pkill -f` 匹配到自己的命令行 | `[p]attern` 写法；停止和重启分两次调用；viz 服务改 pid 文件 |
| Windows 写出的脚本是 CRLF | 上传后 `sed -i 's/\r$//'` |
| 关机命令在下载失败时照样执行 | 关机放在下载成功之后（`&&`）；`safe_get` 先写 .part |
| 远端缺本地才有的数据文件（如 `final.jsonl`、`pp_valid.jsonl`） | 数据放 `configs/data/` 随代码包上传 |

## 11. 已确认的结论

1. **负例标签噪声是 critic 召回上不去的主因，清洗比合成有效。** 只清洗约 550 个带噪负例，++ 有效召回 0.471 → 0.619，超过所有合成臂（2026-10-29）。
2. **人工数据够多时，合成数据（含 DPO / GRPO 生成器产出）没有提升 critic。** 第一、二轮 10 组没有一组有效 AUC 超过基线 0.9447；在金标种子上加 G_free 明显错误反而变差（2026-11-01）。只有 203 条种子时 G_free 有小幅显著提升。
3. **critic 完全识破不了的合成样本，多半不是真错。** 35B 判有效、p = 0 的样本 63% 其实没错（2026-10-29）；2B critic P < 0.1 的合成样本 Claude 只确认 11/33（2026-11-03）。「挑 critic 识破不了的」会顺带挑进标签噪声。
4. **加入目标模型自己的回答 + Claude 标注，是唯一同时在金标和留出集上显著提升 critic 排序的数据**（rm1_gold_9b，金标全部错误 AUC 0.9055 → 0.9247，2026-11-02）。
5. **critic 当奖励的回答 GRPO 有效。** Claude 验收：2B 基线 → GRPO 有错回答 70% → 52%、明显 43% → 25%；9B 原始 → GRPO 明显 46% → 20%（2026-11-02）。满意度护栏没有明显损害回答质量。
6. **回答 GRPO 会挖出 2B critic 的专属盲区。** 2B GRPO 回答里 2B critic 只抓到 20% 的明显错误，9B 金标 critic 抓到 80%（2026-11-03）。
7. **2B 漏明显错是比对能力问题，不是找不到证据；漏轻微错是标签标准问题。** 只给证据段 2B 更差；同数据 9B 明显错判出 24/30，2B 6/30；轻微的范围 / 确定性偏移两个模型都漏，训练集 A 行约 10% 正是这类藏错（2026-11-03 至 11-04）。
8. **拒答是标签问题，修正后立刻改善。** rm1__mcgold_ref 拒答错误 12/12 判出（基线 0），clear AUC 0.748 → 0.795，RAGTruth++ AUC 不变（2026-11-04）。
9. **合成的边界错句没有教会 critic 区分边界错和正确改写。** h2（清洗后）比 h2n 好，但只回到基线水平，边界区误报不降（2026-11-03）。
10. **RM3 在已过门槛的边界样本上近似随机（AUC 0.51）；严重程度 RM 明显更好。** sev__mc P(显然) AUC 0.805（旧 RM3 0.551），盲区独立测试 0.714（旧 0.517），盲区精度约 63%；学习曲线已平（2026-11-03 至 11-04）。
11. **生成器奖励应偏向 critic 边界，且「明显的错」必须吃亏。** a7（固定保底 0.1 + 4P(1−P)）在同等目标产量下纯度最高；分级保底或帐篷形会让明显的错或「不造错」占上风（2026-11-03）。
12. **RM2 区分合成与自然主要靠生成器的写法和「错得明显」，不是表面特征**（表面特征 AUC 0.60–0.61）；RM 分数在生成器 GRPO 里容易被钻空子（9B 时期改法名 hack、类型塌缩）。
