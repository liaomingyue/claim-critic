# 核心种子集与金标标注规范（v1）

选 100 条回答，由 Claude 按统一标准标注，作为核心种子集和核心标准。提示词在 `ragtruth/gold.py`（`SYSTEM`），规则改动要升版本，并重标已标数据。

## 数据怎么用

- 种子集：100 条回答，错误尽量分散，用来训练。
- 金标评测集：现有测试集 402 条回答全部重标，不挑错误分布，用来评测，留一小部分做校准。
- 两者规范相同、数据不重叠。

## 标注单位和盲标

- 一次标一整条回答，逐句给结论；句子只和原文比，前文只用来理解代词和指代。
- Claude 不看 RAGTruth 标签，也不看任何模型的判定。
- 种子集独立标两遍，不一致的句子再裁决。

## 判定标准

句子说了原文没有说、也不能直接推出的内容，就是错误；拿不准时算错误（严格口径）。

算错误：

- 数字、日期、人名、数量被改或凭空出现；事实归到了错误的人或对象上。
- 确定性或范围被改：“提议罚款”写成“已罚款”，“一位制片人”写成“制片人们”，“可能”写成“很可能”。
- 添加具体细节；添加原文没有的评价、目的、后果或建议，包括含糊的附加语（“这是个好选择”）。
- 意思有偏移的近义词（“provided”写成“promised”）。
- 把不同段落的内容拼成原文没有的说法。
- 回答对自身可核实的错误说法（如“以下摘要共 42 字”而实际不符），记为 `self_description`、`minor`。

不算错误：

- 真正的同义改写、如实的概括、语序调整；读者都知道的等价说法（缩写、常见别称）。
- 不含事实内容的套话（“Sure, here is a summary”）、对问题的复述。
- 省略信息，除非省略后剩下的内容变成错的。
- 能从原文直接推出的内容（如简单计算）。
- 回答如实说明原文没有提供某信息。

## 每句记录

| 字段 | 取值 |
|---|---|
| `is_error` | true / false |
| `type` | `conflict`（原文有不相容的说法）/ `baseless`（原文没提）/ `none` |
| `mechanism` | `wrong_attribution`、`number_or_date`、`contradicts_source`、`merged_across_passages`、`added_specific_fact`、`vague_evaluation_or_addon`、`certainty_or_scope_shift`、`near_synonym_shift`、`unsupported_inference`、`self_description`、`other`、`none` |
| `severity` | `clear`（认真的读者会认为是事实错误）/ `minor`（技术上无依据、影响小、可能有分歧）/ `none` |
| `evidence` | 原文相关片段；原文没提时为空 |
| `note` | 一句话说明 |

评测时全部错误（clear + minor）和明显错误（clear）的召回都要报。

## 选种子回答

- 只用 QA 和 Summary；每个原文只留一条回答；不用测试集、校准集的原文。
- 先按任务和生成模型分层随机选 40 条，看真实分布；再分批补 60 条，补缺的错误机制。
- 覆盖目标：每种机制至少约 8 条，单种不超过 25%；凑不够如实报告。
- 不按 RM1 分数只挑难的，高、中、低分都要有。
