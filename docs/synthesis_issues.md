# 错误合成：卡在哪，打算怎么办

错误合成这一环的任务是给 critic 造训练样本：拿 2B 模型自己写的回答，在 critic 判为没错的句子上改一句，改出来的句子要同时满足三条——是真错、读起来自然、当前的 critic 认不出。此外整批样本还要足够多样。闭环转了两轮之后，这一环成了瓶颈。这份文档把问题拆开讲清楚：每个问题的证据是什么，哪些应对已经有数据支持，哪些还只是打算。

文中的数字，除特别说明外，来自历次送 Claude 核实的 3,682 条合成样本。这些样本送审前都按“critic 拿不准、验证模型认为是真错且自然”筛过，所以它们代表的是筛选之后的质量，不是生成器的原始产出。Claude 在这里扮演高质量的人工审核者：闭环的目的不是凭空提升，而是找出自己的盲区并补上，外部的核实信号是这个过程的一部分。

## 现状

| 指标 | 数值 |
|---|---|
| 筛选前，每 2,048 条原始产出里够得上送审门槛的 | 约 40 条，迭代四轮没有涨 |
| 送审样本里是真错的 | 66%（明显错 26%） |
| 读起来自然的 | 84% |
| 真错且自然的 | 52% |
| 真错、自然、类型和要求一致的 | 24% |
| 类型和要求一致的（全部样本 / 只看真错） | 28% / 42% |

2B 和 9B 两个生成器的真错比例相同（66%、67%），差别在自然度（77% 对 88%）和类型一致率（22% 对 31%）。

两轮闭环的变化：第一轮高分段的真错比例是 64–93%，第二轮降到 52–67%，而且以细微错为主。

## 问题一：三个条件同时满足的比例低

### 为什么低

三个条件两两相克，这是结构性的，不是哪个模型没训好。

- **“critic 认不出”和“真错”相克。** 按 critic 打分低来筛，筛的是 critic 最有把握没错的句子，而 critic 大部分时候是对的。我们直接量过这一点：在模型自己写的回答里，2B critic 判错而更强的模型放过的句子，86% 确实没错。
- **“自然”和“真错”相克。** 送审样本里，没错的有 94% 自然，细微错 86%，明显错只有 68%。改得越重越确定是错，也越像改过的。
- **把关的模型和 critic 一起看不见。** 验证模型和 critic 同源，在 critic 的盲区里排序 AUC 只有 0.67–0.71。它能做预排序，定不了案，所以每条进训练集的样本最终都要靠外部核实。

### 为什么两轮就到头

每一轮吃掉的是盲区里最好造的那一层。生成器、验证模型在两轮之间没有变强，送审质量只会随着好造的错被用完而下降。同时闭环只知道“补”，不知道盲区长什么样：造错一直按固定的 9 个类型来，而 critic 实际漏掉的是更细的模式（限定词丢失、角色颠倒、事件错配）。

### 对 GRPO 的影响

用 GRPO 训生成器时，奖励是三个条件的乘积。合格样本占原始产出约 2%，一组十几条采样里通常一条合格的都没有，全组奖励都是 0，没有可以比较的差异，梯度就是噪声。这不是奖励设计的细节问题：合格率低到一定程度，任何靠组内比较的方法都学不动。

### 应对

按顺序做，前面的做完再考虑后面的。

1. **先把合格率抬起来，再上 GRPO。** GRPO 适合在“一组里有好有坏”时拉开差距，不适合从接近零的地方起步。起步阶段用已核实的合格样本做监督训练：两轮下来真错且自然的有 1,928 条，每条都记着当时选了哪一句、怎么改的。只用它们重训生成器，学的是“这类错该在什么样的句子上、用什么改法造”。（未做。之前几轮重训没涨，但当时喂的是同源验证模型筛的数据，分不清是学不会还是数据脏。）
2. **奖励给出部分分。** 三个条件相乘时，满足两条和一条都不满足得分一样。改成分级：先奖励“是真错且自然”，critic 打分作为加成而不是门槛；critic 的合格区间先放宽，合格率上来后再收紧。这样一组里能分出高下。（未做。）
3. **让“真错”尽量由构造保证。** 对能写成确定性操作的错——对调原文里两个人的言行、把数量的对象或单位换成原文里的另一个、把事件安到另一个时间地点——改完必然和原文矛盾，不需要模型来判真假。真错不再依赖一个和 critic 相关的判断者，再按“critic 认不出”筛就不会把真错筛掉，三个条件里最硬的一对冲突就解开了。它只覆盖能写成操作的那几类，推断类造不了。（未做。）
4. **让每次核实同时训练三个模型。** 现在核实结果只用来给 critic 加样本。被否掉的样本同样是信息：它们正是验证模型判错的地方。每轮核实之后，critic、验证模型、生成器都更新，下一轮的送审质量才会涨。（计划中的小步循环，未做。）
5. **前置筛掉不值得造的。** 见问题二。

验证模型不可靠时，GRPO 还有一个风险：生成器会去优化验证模型的错误，造出“验证模型以为是真错、其实不是”的样本。所以第 3、4 条要在 GRPO 之前就位。

## 问题二：造出来的类型和要求的不一致

### 现象拆解

类型一致率只有 28%，但不一致不是一种情况，而是三种：

| 情况 | 占全部样本 | 说明 |
|---|---|---|
| 没造出错 | 34% | 和类型无关 |
| 是真错，但成了别的类型 | 38% | 见下 |
| 照做了 | 28% | |

再往下看“没照做”的原因：

- **选错了句子。** 要求造数字错的 230 条里，133 条选的句子里没有数字；其中 70% 的回答里其实有别的句子带数字。
- **回答本身不适合。** 没有数字的回答造不出数字错。但这种情况是少数：按简单规则看，八成的回答对所要求的类型是有原料的。
- **有原料也没去用。** 要求造数字错、选中的句子里也确实有数字的 102 条里，真把数字换成另一个数字的只有 31 条，这 31 条有 61% 造成了数字错。其余的要么数字原样没动、改了别处（37 条，几乎都不是数字错），要么把数字删掉换成了模糊说法（26 条）。所以问题不是照着做了没做成，而是多数时候没照着做。
- **照做率低不是筛选造成的。** 我们一度以为，是送审前按"critic 拿不准"筛选时把老实照做的样本筛掉了。拿一批没筛过的样本验证（最早的生成器在 70 篇原文上每个类型都造，共 964 条，全部核实过），类型一致率是 27%，和筛过的各批一样。生成器从一开始就是这个水平。
- **照做了的样本，critic 多半认得出。** 同一批没筛过的样本里，critic 打分越低，照做的越少、真错也越少：

  | critic 打分 | 条数 | 真错 | 类型一致 |
  |---|---|---|---|
  | 低于 0.5 | 287 | 41% | 12% |
  | 0.5–0.8 | 199 | 70% | 29% |
  | 0.8 以上 | 478 | 92% | 34% |

  数字类最典型：真换了数字的，七成成功，但 critic 平均打 0.77，认不出的只有 12%。各类型里"照做且 critic 认不出"的比例，范围类 44%，近义偏移 20%，张冠李戴 14%，其余都不超过 12%，数字类和添加事实只有 5%。也就是说，照做率和"critic 认不出"在多数类型上是互斥的；范围类是唯一的例外，这也是前两轮闭环在它上面见效的原因。

同一条回答、同一个类型造两次，成败几乎不相关（去掉类型本身的差别后相关系数 −0.02）；两次选中同一句时相关系数是 0.27。也就是说，成败主要取决于选了哪一句和这一次怎么改的，回答整体的影响很小。

### 应对

1. **前置判断：先看适不适合，再决定造不造。** 用规则回算的结果：

   | 要求的类型 | 规则 | 选中的句子满足规则时 | 不满足时 |
   |---|---|---|---|
   | 数字或日期 | 句子有数字，原文还有别的数字 | 24% | 6% |
   | 确定性或范围 | 句子有限定词 | 43% | 28% |
   | 张冠李戴 | 句子有专名，原文另有两个以上专名 | 23% | 17% |

   方向是对的，幅度不够。换成正经的实体识别重算，数字类的结果不变（句子里有数字类实体时 25%，没有时 5%）；张冠李戴类仍然区分不开（句子里有人名或机构时 22%，没有时 18%），说明这类错的成败不取决于有没有名字，而取决于名字和言行的对应关系，这要抽取关系才能判断。我们还看过“原文里可替换的数字越多越容易成”，粗分时有这个趋势，按识别出的类型细分后没有再现，不能当结论。
2. **前置判断用规则，不用模型。** 我们训过一个适合度模型：输入是原文、回答、一个错误类型，输出按这个类型去造能不能成；每个类型单独打分，不指定目标句（生成器本来就是从整段里自己挑）。训练用 3,682 条真实尝试，按原文留出 631 条评测。结果没有学到可用的信号：整体 AUC 0.48，低于“只看类型的平均成功率”这个基线的 0.60；每个类型内取分数最高的三分之一，成功率只比该类平均高 0.4 个点。样本最多的范围类（249 条）类型内 AUC 是 0.48。个别类型看着有区分力（添加具体事实 0.89、无依据推断 0.69、张冠李戴 0.63），但留出集里每类只有 6–13 条成功样本，不能当真。这和上面的回算一致：在整条回答这一层，成败几乎不可预测。所以前置判断只做一件事——用规则挡掉明显没有原料的回答，条件写进错误体系里每个类型的适用条件。
3. **挑句子交给生成器学。** 前置规则只管“这条回答值不值得造”。“在哪一句上造”靠问题一里的监督训练解决。
4. **类型分细，并且写成可执行的。** “改数字”太宽，critic 认不出的是“把数字的对象换掉”这样的具体模式。错误体系里每个条目应该带上适用条件、构造操作、检查方法，才能既指挥得动生成器，又查得出它有没有照做。
5. **用实际造成的类型来记账。** critic 训练只要求样本是真错、自然、critic 认不出，并不要求它符合当初的指令。类型一致率影响的是“想补哪类就能补到哪类”的定向能力。所以配额和覆盖率按核实后的实际类型统计，不按要求的类型统计；偏离的样本照常使用。

### 类型标签本身可不可靠

- 能交叉验证的部分没有问题：数字类可以用字符串比对独立检查，核实标为“别的类型”的样本里只有 21% 动了数字，而且多是顺手删掉，真正的错在别处。
- 但一条错只标一个类型，而很多错同时属于两类。改写动了数字的真错有 540 条，被分散标进了 9 个类型。这不是标错，是 9 个类型把“错在什么上”和“怎么错的”捆在一起，本身有重叠。
- 重复标注的一致性没有量过：同一条内容标过两次的只有 4 对。在用类型标签训练模型之前，应该抽一批重标，按类型看一致率。

## 问题三：多样性怎么量、怎么保证

多样性目前没有系统地量过。下面是手头能算出来的，以及打算采用的量法。

### 现有样本的情况

以 1,928 条真错且自然的样本为准：

| 角度 | 数值 | 怎么看 |
|---|---|---|
| 原文覆盖 | 646 篇原文、941 条回答；单篇最多 18 条；前 10% 的原文占 34% | 有集中，需要每篇设上限 |
| 类型 | 实际类型的有效类别数 7.8（满分 9）；范围类 552 条，数字类 86 条 | 分布不均，但比要求时的分布（有效类别数 6.9）更散 |
| 位置 | 改在首句 19%、末句 29%、中间 52% | 没有明显偏向 |
| 改法 | 改写描述归并后只有 134 种模板，前四种都是“把 A 换成 B” | 几乎全是替换，删除和添加很少 |

最后一行是最明显的问题：样本在类型标签上看着分散，改法上却高度单一。

### 打算怎么量

多样性要回答的是“这批样本覆盖了多少种 critic 需要学的东西”，所以分三层量：

1. **覆盖**：按错误体系的维度（错在什么上、怎么错的、改法、任务类型）交叉成格子，看有样本的格子占多少、样本在格子间的均匀程度（有效类别数）。现在只能按 9 个类型量，粒度不够。
2. **重复**：同一篇原文、同一句话、同一种改法模板各占多少；改写前后的差异做近似去重。
3. **对口**：和模型真实犯的错比。每轮从模型自己的回答里抽一小批送审，得到真实错误在各格子上的分布，再看合成样本的分布和它差多少。合成样本再分散，如果集中在模型不犯的错上，对 critic 也没用。

最终的检验是有用性：加进训练后 critic 在对应格子上的召回有没有涨。前三层是便宜的代理。

### 怎么保证

- **按格子定配额**，由盲区决定各格子要多少，而不是让生成器自由发挥——它会集中到最容易的改法上。
- **每篇原文、每条回答设上限**，相同改法模板去重。
- **扩充改法**：现在的生成器几乎只做替换。构造操作清单里应该包括删除限定、对调、跨句合并这些替换之外的改法。
- **GRPO 阶段加组内去重**：同一组里改法重复的样本降权，避免生成器收敛到一种稳拿分的改法。（未做。）

## 另外几个和合成有关的问题

- **只能补到“拿不准”的一层。** 两轮见效的样本都来自 critic 打分 0.1–0.5 的区间。critic 高置信放过的那部分（打分低于 0.1），合成的命中率太低，核实不起。这一层目前没有办法。
- **合成的错不等于模型会犯的错。** 样本是在 critic 判为没错的句子上改出来的，改法由生成器决定。模型真实的错是什么样，要靠从模型自己的回答里抽样核实来校准。直接从模型回答里挖样本的效率很低：critic 打分 0.1–0.5 的句子里只有约 3% 是明显错，所以它适合当测量，不适合当产能。
- **不核实不行。** 做过对照：近义偏移和张冠李戴两类不经核实直接加进训练，混进约三分之一不是错的样本，critic 在明显错上显著变差。
- **生成器自述的改法靠不住。** 让它自己说明改了什么类型，和实际对得上的只有 2–27%。类型必须由外部判定。

## 小结：哪些有数据，哪些还是打算

| 结论或做法 | 状态 |
|---|---|
| 三个条件相克、同源验证模型在盲区里失效 | 有数据 |
| 不一致分三种，选错句子占很大一块 | 有数据 |
| 前置规则能提高照做率，但幅度有限 | 有数据（事后回算，没有留出集） |
| 原文里可替换的数字越多，数字错越容易造成 | 细分后没有再现，不成立 |
| 照做率低不是筛选造成的；照做的样本 critic 多半认得出 | 有数据（未筛选的 964 条） |
| 有原料时多数没去改它（数字类 102 条里只有 31 条换了数字） | 有数据 |
| 适合度模型学不到信号，前置判断用规则 | 有数据（留出 631 条） |
| 构造式改写、监督重训生成器、分级奖励、三个模型同时更新 | 打算，未做 |
| 多样性的三层量法 | 打算，未做；现有的只是粗略统计 |
| 类型标签的重标一致率 | 未量 |
